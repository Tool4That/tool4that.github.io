================================================================================
 01: WINDOWS 11 HARDENING: SOLUTION WALKTHROUGH
     Windows 11 26H2 (Pro / Enterprise)
 Training reference for virtual machines you own or are authorized to change.
 Three levels: L1 Doorman, L2 Watchman, L3 Hunter. Every item = COMMAND, WHY,
 NOTE, and the hardening AREA it belongs to; ALSO adds a second caution when
 an item needs one. No scripts by design: type it, read it, explain it. Item
 IDs match the Lockdown Drills trainer for this OS.
 Unofficial practice; not affiliated with or endorsed by Microsoft.

 PS> runs in an elevated PowerShell and CMD> in an elevated Command Prompt.
 Type what follows the prefix, and replace each <name> with a real value. GUI:
 lines walk through a window, and indented lines show values to set or read.
 Each level names the Defense Ladder unit to learn first:
 https://freeapp4that.store/defense-ladder/

 HARDENING AREAS (CIS Critical Security Controls v8.1)
   Account management ........ CIS Control 5
   Access control ............ CIS Control 6
   Secure configuration ...... CIS Control 4 (software inventory: Control 2)
   Patching .................. CIS Control 7
   Malware defenses .......... CIS Control 10
   Audit logging ............. CIS Control 8
   Also tagged: Data protection (CIS Control 3); Investigation (forensics
   basics: answer questions and preserve evidence before you change things).

------------------------------ DOORMAN -----------------------------------------
 Lock the doors. These are the fixes that are safe on almost any machine and
 close the most common gaps: users, admins, passwords, firewall, updates,
 Defender, and unapproved software. Learn it first: Defense Ladder s2, "Windows
 11 hardening."
--------------------------------------------------------------------------------
[B-00] Scenario brief and evidence first
  AREA: Investigation (forensics basics)
  GUI: open the scenario brief (the documented requirements for this machine) and write down authorized users, admins, required services, and anything forbidden
  CMD> dsregcmd /status   (AzureAdJoined and DomainJoined show who else can push settings to this PC)
  WHY: Removing a user, role, or service the business needs is an availability
       failure. Read the brief, then answer the investigation questions before
       any change (Defense Ladder f1).
  NOTE: Unfamiliar software is distinct from unauthorized software: trace it,
        and ask the owner before removing an agent (Defense Ladder s1).

[B-01] List local users
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Select-Object Name,Enabled,PasswordRequired,LastLogon
  CMD> net user
  PS> Get-Command *LocalUser*   (finds the account cmdlets this item uses)
  PS> Get-LocalUser | Get-Member   (lists every property you can select, such as Enabled)
  PS> Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' | Select-Object EditionID,CurrentBuild
  GUI: Win+R, lusrmgr.msc (not available on Home)
  WHY: Unauthorized accounts are backdoors: compare the list to the brief's
       authorized users. Set and require passwords on enabled, authorized
       accounts: net user <name> * /passwordreq:yes.
  NOTE: PasswordRequired False only permits blank passwords; Windows Setup
        accounts often show False with a password set. Confirm passwords in
        Control Panel, User Accounts, Manage another account: look for
        Password protected.
  ALSO: EditionID Core means Home; ProductName can still say Windows 10. Home
        leaves out lusrmgr.msc and secpol.msc: use Settings, Accounts, Other
        users, or netplwiz.

[B-02] Remove an unauthorized user
  AREA: Account management (CIS Control 5)
  PS> Get-ScheduledTask | Where-Object { $_.Principal.UserId -like '*baduser' } | Select-Object TaskPath,TaskName
  PS> Get-CimInstance Win32_Service | Where-Object StartName -like '*baduser' | Select-Object Name,StartName,PathName
  PS> Remove-LocalUser -Name "baduser"
  CMD> net user baduser /delete
  CMD> net user baduser /active:no
  PS> Disable-LocalUser -Name "baduser"
  PS> Enable-LocalUser -Name keola   (undo a disable once the brief confirms the account belongs)
  WHY: Deleting removes the login path and the profile's persistence hooks.
       Remove only accounts the brief leaves out; when the brief is unclear,
       disable first (/active:no) and ask the owner.
  NOTE: Answer every investigation question that names the account. Handle
        each scheduled task or service running as that account; the first two
        commands find them.
  ALSO: Deleting keeps C:\Users\baduser: search it for evidence before
        removing the folder.

[B-03] Audit the Administrators group
  AREA: Account management (CIS Control 5)
  PS> Get-LocalGroupMember -Group Administrators
  PS> Get-Help Get-LocalGroupMember -Examples   (worked examples; run Update-Help once, online, for the full text)
  CMD> net localgroup Administrators
  CMD> net localgroup "Backup Operators"
  CMD> net localgroup Administrators baduser /delete
  PS> Remove-LocalGroupMember -Group Administrators -Member baduser
  CMD> net localgroup Administrators alice /add
  WHY: An admin can switch off every other control. Least privilege is the
       single highest-value idea in system hardening. Demote users the brief
       calls standard; promote only its listed admins.
  NOTE: A signed-in demoted user keeps admin rights until signing out: Task
        Manager, Users, Sign out.
  ALSO: Backup Operators, Remote Desktop Users, and Remote Management Users
        also grant power where they exist; compare each with the brief
        (Get-LocalGroup lists every group).

[B-04] Disable Guest and the built-in Administrator
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Where-Object { $_.SID -like '*-50[01]' } | Select-Object Name,Enabled,SID
  CMD> whoami /user
  CMD> net user Guest /active:no
  PS> Disable-LocalUser -Name Guest
  CMD> net user Administrator /active:no
  WHY: Attackers brute-force well-known accounts by name, and Guest allows
       anonymous-style access. The built-in Administrator's SID ends in -500
       and Guest's in -501, so a SID match finds both despite renames.
  NOTE: If the brief says you sign in as Administrator, keep it enabled with a
        strong password. If whoami /user ends in -500, this session is that
        account.
  ALSO: Rename only when the brief or policy asks, and last (Rename-LocalUser
        -Name Administrator -NewName <new name>). The SID stays, so disabling
        and a strong password carry the protection.

[B-05] Strong passwords for every user
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Select-Object Name,Enabled,PasswordLastSet,PasswordExpires
  CMD> net user alice *
  PS> Get-LocalUser | Where-Object { $_.Enabled -and $_.Name -ne $env:USERNAME } | Set-LocalUser -PasswordNeverExpires $false
  CMD> net user alice /logonpasswordchg:yes
  WHY: Weak, shared, or blank passwords are the top way in. Password never
       expires defeats the aging policy: clear it first, then ask for a change
       at next logon. The * makes net user prompt, hiding the password from
       screen and history.
  NOTE: Set the password policy first (B-06, B-07) so each new password must
        meet it. Give the account a fresh password before clearing Password
        never expires: clearing it on an old password expires it at once, and a
        service or task that signs in with it needs the new one too. Change your
        own sign-in password only when the brief says so. An administrator reset
        locks the user out of files they encrypted and of saved passwords.
        Record every changed password somewhere safe (on paper, in a lab).

[B-06] Password policy
  AREA: Account management (CIS Control 5)
  CMD> net accounts /minpwlen:12 /maxpwage:60 /minpwage:1 /uniquepw:24
  CMD> net accounts
  GUI: secpol.msc, Account Policies, Password Policy. Turn on 'Password must
       meet complexity requirements' and keep 'Store passwords using reversible
       encryption' off.
  WHY: Length matters most. A minimum age keeps users from cycling through the
       24-password history. Reversible encryption is disguised plaintext;
       turning it off protects only new passwords, so reset older ones.
  NOTE: The brief overrides these samples. The CIS Benchmark recommends 14+
        characters, a 24-password history, a 1–365-day maximum age, and a
        1-day minimum. net accounts stops at 14 and skips complexity.
  ALSO: Past 14, enable Relax minimum password length limits under Password
        Policy (secpol.msc or secedit), then set the length. Set secedit's
        PasswordComplexity = 1 on any edition, Home included (Hunter A-01).

[B-07] Account lockout policy
  AREA: Account management (CIS Control 5)
  CMD> net accounts /lockoutthreshold:5 /lockoutduration:30 /lockoutwindow:30
  WHY: Turns an online brute force from thousands of guesses a minute into
       five per half hour. The scenario brief sets the numbers; that rate
       reflects one sample brief.
  NOTE: The CIS Benchmark recommends a duration and reset window of 15 minutes
        or more. Its threshold is 5 or fewer and above 0 (0 never locks, which
        is a finding).
  ALSO: The built-in Administrator locks only with Allow Administrator account
        lockout Enabled (secedit template: AllowAdministratorLockout = 1,
        Hunter A-01), and only for network sign-ins like Remote Desktop.
        Console sign-in stays available.

[B-08] Firewall on for all profiles
  AREA: Secure configuration (CIS Control 4)
  PS> Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True
  PS> Get-NetFirewallProfile -PolicyStore ActiveStore | Select-Object Name,Enabled,DefaultInboundAction
  CMD> netsh advfirewall set allprofiles state on
  CMD> netsh advfirewall show allprofiles
  GUI: Settings, Privacy and security, Windows Security, Firewall and network
       protection.
  WHY: Default-deny inbound covers the service you have not found yet.
       Misconfigured machines often have exactly one profile off, usually
       Public.
  NOTE: DefaultInboundAction should be Block. ActiveStore shows values in
        force, Group Policy included; the plain view reads NotConfigured for
        values left at default (Block inbound). Watchman covers allow rules.

[B-09] Windows Update: run it and automate it
  AREA: Patching (CIS Control 7)
  GUI: Win+R, ms-settings:windowsupdate (Settings, Windows Update): Resume updates if paused, then Check for updates; Advanced options: receive updates for other Microsoft products
  PS> Get-Service wuauserv,BITS,UsoSvc | Select-Object Name,Status,StartType
  PS> Set-Service -Name wuauserv -StartupType Automatic; Start-Service wuauserv
  CMD> reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate /s
  PS> Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 5
  PS> winget upgrade
  PS> winget upgrade --all --silent --accept-package-agreements --accept-source-agreements
  CMD> shutdown /r /t 0   (restart to finish installing updates, after you save your work)
  WHY: Patching closes the holes scanners find. Confirm Get-HotFix shows a
       recent install date and automatic updates stay on; I-18 covers policy
       values that stop them while the service runs.
  NOTE: Run updates first in the background; recheck after each restart until
        up to date. wuauserv ships as Manual (starts on demand); Disabled is
        the finding. Save work before any reboot.
  ALSO: Windows Update patches Windows and Microsoft apps; browsers and others
        use winget or their own updater. Remove prohibited apps (B-11) before
        winget upgrade --all, so it updates only what stays.

[B-10] Defender: real-time on, definitions current, scan
  AREA: Malware defenses (CIS Control 10)
  PS> Get-MpComputerStatus | Select-Object AntivirusEnabled,RealTimeProtectionEnabled,AntivirusSignatureLastUpdated
  PS> Set-MpPreference -DisableRealtimeMonitoring $false
  PS> Update-MpSignature
  PS> Start-MpScan -ScanType QuickScan
  PS> Start-MpScan -ScanType CustomScan -ScanPath C:\Users
  PS> Get-MpThreatDetection | Select-Object InitialDetectionTime,ProcessName,Resources
  GUI: Win+R, windowsdefender: (Windows Security), Virus and threat protection,
       Manage settings: Real-time protection and Tamper Protection On.
  WHY: Real-time protection is the baseline malware control. Neglected or
       compromised machines have it off, or carry exclusions that hide
       malware. Get-MpComputerStatus confirms RealTimeProtectionEnabled is
       True.
  NOTE: Answer the investigation questions before any scan, because a scan can
        quarantine the file a question asks about. If Tamper Protection blocks
        Set-MpPreference, switch real-time protection on in the GUI.
  ALSO: In Get-MpThreatDetection, Resources names each detected file: record
        that path. Then remove the program that dropped the file when the
        brief leaves that program out.

[B-11] Remove unapproved software
  AREA: Secure configuration: software (CIS Controls 2 and 4)
  PS> Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*, HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*, Registry::HKEY_USERS\*\Software\Microsoft\Windows\CurrentVersion\Uninstall\* -ErrorAction SilentlyContinue | Select-Object DisplayName,DisplayVersion,Publisher,UninstallString | Sort-Object DisplayName
  GUI: Settings, Apps, Installed apps (or appwiz.cpl)
  PS> winget list
  PS> winget uninstall --id WiresharkFoundation.Wireshark --exact
  PS> Get-AppxPackage -AllUsers | Select-Object Name | Sort-Object Name
  PS> Get-AppxPackage -AllUsers *xbox* | Remove-AppxPackage -AllUsers
  WHY: Hacking tools, games, torrent clients, and remote-access tools are
       acceptable-use violations and attack surface.
  NOTE: Software the brief requires stays. The registry listing is instant;
        Win32_Product is slow and can trigger repairs. Store apps need
        Get-AppxPackage instead; portable tools need a file search (B-12,
        A-06).
  ALSO: HKEY_USERS adds signed-in users' own apps. Remove Npcap, a separate
        capture-tool install, when the brief omits packet capture. After
        removing remote-access tools, seek leftover services (I-04) and
        firewall rules (I-12).

[B-12] Find unapproved media and loose executables
  AREA: Data protection (CIS Control 3)
  PS> Get-ChildItem -Path C:\Users -Recurse -Force -File -Include *.mp3,*.mp4,*.wav,*.avi,*.mkv,*.flac,*.mov,*.m4a,*.mpg,*.mpeg,*.ogg,*.flv,*.wma,*.aac -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\|^C:\\Users\\(All Users|Default User)\\' | Select-Object FullName
  CMD> dir /s /a /b C:\Users\*.mp3 C:\Users\*.mp4
  CMD> del /s /a C:\Users\*.mp3 C:\Users\*.mp4   (after dir /s /a /b lists the same files and the brief bans them; del also reaches AppData, where apps keep their own sounds, so check that list for AppData paths first)
  CMD> rd /s /q "C:\Users\<user>\Music\<folder>"   (a folder of banned files, after dir lists it: rd removes the folder and everything in it)
  PS> Get-ChildItem -Path C:\Users -Recurse -Force -File -Include *.mp3,*.mp4 -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\' | Remove-Item -Force   (after the list above is reviewed and any file a question names is hashed)
  PS> Get-ChildItem -Path C:\Users -Recurse -Force -File -Include *.exe,*.bat,*.cmd,*.ps1,*.vbs,*.hta,*.py,*.jar,*.zip,*.7z,*.rar -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\Local\\(Microsoft|Packages)\\|^C:\\Users\\(All Users|Default User)\\' | Select-Object FullName,LastWriteTime
  PS> Get-Item 'C:\Users\<user>\Downloads\<file>' -Stream * | Select-Object Stream,Length
  PS> Get-Content 'C:\Users\<user>\Downloads\<file>' -Stream Zone.Identifier   (ZoneId=3 marks a file downloaded from the internet)
  PS> Unblock-File -Path 'C:\Users\<user>\Downloads\<file>'   (only for an expected file from a trusted source: it removes the downloaded-from-the-internet mark)
  CMD> tar -tf "C:\Users\<user>\Downloads\<archive>.zip"
  WHY: Many acceptable-use policies ban personal media on work machines, and
       scripts sitting in user folders are often the planted backdoor. Confirm
       each file against the brief before deleting.
  NOTE: First answer every investigation question naming a file and record its
        hash (B-14); then delete it and log the path. tar -tf lists a .zip's
        contents before you delete it.
  ALSO: Search C:\ too, beyond C:\Users. -Force shows hidden files; the
        filters skip AppData caches and the All Users and Default User links.
        Keep Python and other runtimes the brief needs.

[B-13] Stop obviously unsafe services
  AREA: Secure configuration (CIS Control 4)
  PS> Get-Service -Name ftpsvc,TermService,RemoteRegistry,SNMP -ErrorAction SilentlyContinue | Select-Object Name,Status,StartType
  PS> Stop-Service -Name RemoteRegistry; Set-Service -Name RemoteRegistry -StartupType Disabled
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 1
  PS> Get-NetFirewallRule -Group '@FirewallAPI.dll,-28752' -ErrorAction SilentlyContinue | Disable-NetFirewallRule
  CMD> reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services" /v fDenyTSConnections
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Remote Assistance' -Name fAllowToGetHelp -Value 0
  GUI: Win+R, SystemPropertiesRemote: clear Allow Remote Assistance connections to this computer when the brief rules out remote help
  PS> Get-NetFirewallRule -Group '@FirewallAPI.dll,-33002' -ErrorAction SilentlyContinue | Disable-NetFirewallRule
  PS> Get-NetTCPConnection -State Listen -LocalPort 21,3389 -ErrorAction SilentlyContinue
  GUI: Settings, System, Remote Desktop: Off unless the brief requires it.
       services.msc for the rest: set Startup type to Disabled.
  WHY: Telnet and FTP send cleartext credentials; Remote Registry accepts
       network edits. RDP draws brute force; Remote Assistance, allowed by
       default on Windows 11, hands an invited helper the desktop.
  NOTE: If the brief requires RDP, FTP, or SSH, harden it (I-11) rather than
        stop it. Turning Remote Desktop off takes the setting plus its firewall
        group. The @FirewallAPI names work in any display language. Home lacks
        the Remote Desktop group, so that line returns quietly there.
        fDenyTSConnections under the Terminal Services policy key is Group
        Policy and beats the Settings switch. A value of 0 there forces Remote
        Desktop back on, so a missing-value error is the good result. The last
        line returns empty once FTP and Remote Desktop stop listening.

[B-14] Hash a file for an investigation question
  AREA: Investigation (forensics basics)
  PS> Get-FileHash -LiteralPath 'C:\Users\<user>\Desktop\<file>' -Algorithm SHA256 | Format-List
  CMD> certutil -hashfile "C:\Users\<user>\Desktop\<file>" SHA256
  PS> Format-Hex -Path 'C:\Users\<user>\Desktop\<file>' | Select-Object -First 1   (the first bytes name the real type: 4D 5A is an .exe, 25 50 44 46 is a PDF; PowerShell 7 adds -Count 8)
  PS> Get-MpThreatDetection | Select-Object InitialDetectionTime,Resources
  WHY: Answer with the named algorithm's exact hex string, which repeats on
       every run. Hash before any Defender scan, cleanup, or move: changed or
       quarantined, the file answers differently or vanishes.
  NOTE: Check each hash's length: MD5 32 hex characters, SHA1 40, SHA256 64.
        certutil defaults to SHA1, so name the algorithm. -LiteralPath reads
        names with [ ] that -Path skips.
  ALSO: Quotes keep paths with spaces whole. If opening the file reports a
        virus, Defender already quarantined it: Get-MpThreatDetection and
        Windows Security, Protection history show the path and time to record.

[B-15] Create the users and groups the brief lists
  AREA: Account management (CIS Control 5)
  PS> New-LocalUser -Name 'kekoa' -Password (Read-Host -AsSecureString 'Password')
  CMD> net user kekoa * /add
  PS> New-LocalGroup -Name Accounting
  CMD> net localgroup Accounting /add
  CMD> net localgroup Accounting kekoa /add
  PS> Add-LocalGroupMember -Group Accounting -Member kekoa
  PS> Get-LocalGroupMember -Group Accounting
  WHY: A listed user or group missing from the machine locks someone out of
       sign-in and the job's files. Create exactly that set; the brief is the
       source of truth.
  NOTE: net user /add places the account in Users only; add the groups the brief
        names, then read the membership back. Security event 4720 records each
        new account.

[B-16] Find files that store passwords
  AREA: Data protection (CIS Control 3)
  PS> Get-ChildItem -Path C:\Users -Recurse -Force -File -Include *.txt,*.csv,*.ini,*.xml,*.log,*.ps1,*.bat -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\Local\\|^C:\\Users\\(All Users|Default User)\\' | Select-String -Pattern 'passw(or)?d|pwd|credential' -List | Select-Object Path,LineNumber,Line
  CMD> findstr /s /i /m /c:"password" C:\Users\*.txt C:\Users\*.csv C:\Users\*.ini
  PS> Get-ChildItem -Path C:\Users\*\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt -Force -ErrorAction SilentlyContinue | Select-String -Pattern 'net user|ConvertTo-SecureString|passw' | Select-Object Path,Line
  PS> Get-ChildItem -Path C:\Windows\Panther\Unattend.xml,C:\Windows\Panther\Unattend\Unattend.xml,C:\Windows\System32\Sysprep\unattend.xml -Force -ErrorAction SilentlyContinue | Select-String -Pattern '<Password>|AdministratorPassword' | Select-Object Path,LineNumber
  CMD> cmdkey /list
  WHY: Passwords in notes, scripts, PowerShell history, or Windows Setup
       answer files expose accounts. Hidden answer-file passwords are only
       encoded: treat them as plaintext. Content search finds them under any
       name.
  NOTE: First answer any investigation question that names the file and record
        its hash (B-14). Then remove or move it where the brief says, and log
        the path.
  ALSO: Review each hit: license and app files match too. cmdkey /list shows
        only the signed-in user's saved passwords, like TERMSRV/<host> for
        Remote Desktop; cmdkey /delete:<target> removes one the brief omits.

------------------------------ WATCHMAN ----------------------------------------
 Check the windows. Policy, services, shares, scheduled tasks, startup items,
 hosts file, listening ports, and logs. This is where the hidden stuff lives.
 Learn it first: Defense Ladder j2, "Group Policy."
--------------------------------------------------------------------------------
[I-01] Audit policy: turn the lights on
  AREA: Audit logging (CIS Control 8)
  CMD> wevtutil sl Security /ms:201326592
  CMD> wevtutil gl Security   (maxSize shows the new limit)
  CMD> auditpol /backup /file:C:\Windows\Temp\audit-before.csv
  CMD> auditpol /set /category:* /success:enable /failure:enable
  CMD> auditpol /get /category:*
  WHY: Without auditing, Event Viewer has nothing to tell you or an
       investigator. Logon, account management, and policy change are the key
       ones.
  NOTE: Mixing auditpol with secpol's basic Audit Policy gives unexpected
        results. Use auditpol here or Advanced Audit Policy Configuration in
        Group Policy, leave the basic node unset, and trust auditpol /get.
  ALSO: wevtutil grows the Security log to 192 MB first, so the extra events
        keep older evidence. auditpol /restore
        /file:C:\Windows\Temp\audit-before.csv undoes the audit change.
        Subcategories, and trimming the noisiest, are A-08.

[I-02] Security Options in secpol.msc
  AREA: Secure configuration (CIS Control 4)
  GUI: secpol.msc, Local Policies, Security Options
      Accounts: Limit local account use of blank passwords to console logon only = Enabled
      Devices: Prevent users from installing printer drivers = Enabled
      Interactive logon: Don't display last signed-in = Enabled (older label: Do not display last user name)
      Interactive logon: Do not require CTRL+ALT+DEL = Disabled
      Network access: Do not allow anonymous enumeration of SAM accounts and shares = Enabled
      Network security: LAN Manager authentication level = Send NTLMv2 response only. Refuse LM & NTLM
      Microsoft network client and server: Digitally sign communications (always) = Enabled
      Shutdown: Allow system to be shut down without having to log on = Disabled
      User Account Control: Run all administrators in Admin Approval Mode = Enabled
  WHY: Classic CIS and STIG level-one settings. Each blocks a named attack:
       blank-password remote logon, username harvesting, LM and NTLMv1
       cracking or relay, SMB relay, shutdown before sign-in, and UAC bypass.
  NOTE: With Do not require CTRL+ALT+DEL Disabled, a VM takes the sequence
        from its window menu or shortcut (Ctrl+Alt+End in Hyper-V and Remote
        Desktop). Command-line forms: registry (A-02) or secedit (A-01).
  ALSO: Releases older than Windows 11 24H2 and Windows Server 2025 still
        accept NTLMv1: check the LAN Manager authentication level there and in
        mixed domains.

[I-03] UAC to Always notify
  AREA: Secure configuration (CIS Control 4)
  GUI: Win+R, UserAccountControlSettings: move the slider to the top, Always notify
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name EnableLUA -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name ConsentPromptBehaviorAdmin -Value 2 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name PromptOnSecureDesktop -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name FilterAdministratorToken -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name ConsentPromptBehaviorUser -Value 0 -Type DWord
  GUI: Control Panel, User Accounts, Change User Account Control settings,
       slider to the top.
  WHY: UAC off silently hands admin processes full rights.
       ConsentPromptBehaviorAdmin 2 prompts on the secure desktop for every
       elevation; default 5 auto-elevates Windows programs.
       FilterAdministratorToken 1 covers the built-in Administrator.
  NOTE: ConsentPromptBehaviorUser 0 refuses standard-user elevation, so admins
        elevate from their own sessions; keep 3 (ask for credentials) where
        the brief has helpdesk staff type admin passwords. Reboot after
        changing EnableLUA.
  ALSO: A Security Options UAC policy replaces the slider at the next refresh;
        gpresult /scope computer /v shows it. With Administrator protection on
        (TypeOfAdminApprovalMode 2, Version notes),
        ConsentPromptBehaviorEnhancedAdmin decides the prompt.

[I-04] Service audit: what runs, from where
  AREA: Secure configuration (CIS Control 4)
  PS> Get-CimInstance Win32_Service | Select-Object Name,State,StartMode,PathName | Sort-Object Name
  PS> Get-Service | Where-Object Status -eq Running | Sort-Object DisplayName
  PS> Get-Service -Name EventLog,mpssvc,WinDefend | Select-Object Name,Status,StartType
  PS> Get-Alias sc   (in Windows PowerShell 5.1, sc runs Set-Content: type sc.exe for the service tool)
  CMD> sc.exe query state= all
  CMD> sc.exe qc <name>
  CMD> sc.exe qtriggerinfo RemoteRegistry   (events that can start a Manual service)
  CMD> sc.exe stop <name>
  CMD> sc.exe config <name> start= disabled
  CMD> sc.exe start <name>   (only a service the brief requires)
  CMD> sc.exe delete <name>   (a planted service only, after it is stopped and its file is reviewed; PowerShell 7 adds Remove-Service, and Windows PowerShell 5.1 uses sc.exe delete)
  PS> Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\SNMP\Parameters\ValidCommunities' -ErrorAction SilentlyContinue
  PS> Stop-Service -Name <name>; Set-Service -Name <name> -StartupType Disabled
  WHY: Flag Telnet, FTP, SNMP, SSDP and UPnP, Remote Registry, Xbox services,
       odd names, and any PathName under C:\Users or C:\Temp (planted). SNMP on
       161/udp answers whoever guesses public or private.
  NOTE: Required services (IIS, DNS, DHCP, OpenSSH, MySQL, Apache) stay running;
        harden their configs instead. Event log, firewall (mpssvc), and Defender
        (WinDefend) stay Running and Automatic; Stopped or Disabled on any of
        them is a finding, except WinDefend when the brief names another
        antivirus. Unlisted SNMP: Remove-WindowsCapability -Online -Name

[A-02] LSA and anonymous-access registry hardening
  AREA: Secure configuration (CIS Control 4)
  PS> $lsa='HKLM:\SYSTEM\CurrentControlSet\Control\Lsa'

  PS> Set-ItemProperty -Path $lsa -Name RestrictAnonymous -Value 1 -Type DWord

  PS> Set-ItemProperty -Path $lsa -Name NoLMHash -Value 1 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name LmCompatibilityLevel -Value 5 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name EveryoneIncludesAnonymous -Value 0 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name ForceGuest -Value 0 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name RestrictRemoteSAM -Value 'O:BAG:BAD:(A;;RC;;;BA)' -Type String
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name allownullsessionfallback -Value 0 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name NTLMMinClientSec -Value 537395200 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name NTLMMinServerSec -Value 537395200 -Type DWord

       users signing in over the network as themselves; RestrictRemoteSAM limits

       stay filtered.
  NOTE: This is the registry form of the Watchman Security Options. A missing
        LocalAccountTokenFilterPolicy is the good result. MSV1_0 and the
        System key always exist, so Set-ItemProperty writes there directly.

        it) under [Privilege Rights] as in A-01 with /areas USER_RIGHTS.
        Changes apply at next sign-in and log 4704 and 4705.

[A-06] Deep persistence and backdoor hunt
  AREA: Malware defenses (CIS Control 10)
  PS> Get-CimInstance Win32_Process | Select-Object Name,ProcessId,ParentProcessId,CommandLine | Sort-Object Name
  CMD> quser   (who is signed in now, at the console or over Remote Desktop: capture it before you change anything)
  CMD> wevtutil epl Security E:\case\<host>-Sec.evtx   (export the logs before you change anything; repeat for System)
  PS> Get-ChildItem C:\ -Recurse -Include nc.exe,ncat.exe,netcat*,mimikatz*,psexec*,*.ps1,*.vbs -ErrorAction SilentlyContinue | Select-Object FullName,LastWriteTime
  PS> Get-CimInstance -Namespace root\subscription -ClassName __EventFilter
  PS> Get-CimInstance -Namespace root\subscription -ClassName __EventConsumer
  PS> Get-CimInstance -Namespace root\subscription -ClassName __FilterToConsumerBinding
  PS> $PROFILE | Select-Object *; Get-Content $PROFILE.AllUsersAllHosts -ErrorAction SilentlyContinue
  PS> Get-ChildItem -Path C:\Users,C:\ProgramData,C:\Windows\Temp -Recurse -Force -File -Include *.exe,*.dll,*.scr -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '^C:\\Users\\(All Users|Default User)\\' | Get-AuthenticodeSignature | Where-Object Status -ne 'Valid' | Select-Object Path,Status
  PS> Get-ChildItem 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree' -Recurse | Where-Object { -not $_.GetValue('SD') -and $_.GetValue('Id') } | Select-Object Name
  CMD> wevtutil sl Microsoft-Windows-TaskScheduler/Operational /e:true
  CMD> autorunsc.exe -accepteula -a * -c -nobanner   (Sysinternals, public)
  WHY: WMI event subscriptions and PowerShell profiles are the persistence
       spots checklists miss; Autoruns shows every auto-start location at
       once. A task with SD deleted runs hidden from Get-ScheduledTask and
       schtasks.
  NOTE: A renamed tool keeps its missing or broken signature. Unsigned
        programs in Users, ProgramData, or Temp are leads; legitimate tools
        ship unsigned too, so check the brief and the publisher.
  ALSO: Get Sysinternals from learn.microsoft.com/sysinternals only, and only
        where policy allows third-party tools. The wevtutil line turns on Task
        Scheduler history, which starts off.

[A-07] NTFS permissions
  AREA: Access control (CIS Control 6)
  CMD> icacls "C:\CompanyData" /save C:\Windows\Temp\acl.txt /t /c
  CMD> icacls "C:\CompanyData"
  CMD> icacls "C:\CompanyData" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "Users:(OI)(CI)RX" /t
  CMD> icacls "C:\CompanyData" /remove:g Everyone /t
  PS> Get-Acl "C:\CompanyData" | Format-List
  WHY: Everyone with Full control on shares or Program Files lets anyone swap
       a binary a service runs as SYSTEM. (OI) object inherit, (CI) container
       inherit, /t recurse, /inheritance:r stop inheriting.
  NOTE: Save ACLs first: icacls C:\ /restore C:\Windows\Temp\acl.txt puts them
        back (restore runs from the parent folder). SIDs work in any display
        language: /remove:g *S-1-1-0 for Everyone, *S-1-5-11 for Authenticated
        Users.
  ALSO: A folder made at the root of C: inherits Authenticated Users Modify,
        so read it before you trust it.

[A-08] Fine-grained auditing and PowerShell logging
  AREA: Audit logging (CIS Control 8)
  CMD> auditpol /set /subcategory:"Credential Validation" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Logon" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Account Lockout" /failure:enable
  CMD> auditpol /set /subcategory:"User Account Management" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Security Group Management" /success:enable
  CMD> auditpol /set /subcategory:"Process Creation" /success:enable
  CMD> reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f
  CMD> auditpol /set /subcategory:"Security System Extension" /success:enable
  CMD> auditpol /set /subcategory:"Audit Policy Change" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Filtering Platform Connection" /success:disable /failure:disable
  CMD> reg add HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v SCENoApplyLegacyAuditPolicy /t REG_DWORD /d 1 /f
  PS> if (-not (Test-Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging')) { New-Item -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging' -Force | Out-Null }
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging' -Name EnableScriptBlockLogging -Value 1 -Type DWord
  PS> Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational'; Id=4104} -MaxEvents 3 | Format-List TimeCreated,Message
  PS> Get-ExecutionPolicy -List   (a MachinePolicy or UserPolicy value comes from Group Policy and wins over the scopes below it)
  PS> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned   (only when you must run your own script: Windows 11 starts at Restricted, and RemoteSigned lets local scripts run while downloaded ones need a trusted signature)
  CMD> auditpol /get /category:*
  WHY: Subcategory settings take precedence over the nine legacy categories once
       Audit: Force audit policy subcategory settings is Enabled
       (SCENoApplyLegacyAuditPolicy 1). Credential Validation writes 4776 for
       every local-account password check, so a guessing run shows beside 4625.
       The command-line value fills the Process Command Line field of every
       4688. Security System Extension writes 4697, which names who installed a
       service. Script Block Logging (event 4104) records what every PowerShell
       script actually did, including the attacker's.
  NOTE: Run it after I-01: a category-wide command rewrites every subcategory in
        its category. Account Lockout has Failure events only (the lockout
        itself, 4740, comes from User Account Management), and Security Group
        Management has Success events only. Filtering Platform Connection floods
        the log after a category-wide run; turn it back on when the brief asks
        for connection auditing. auditpol names drop the Audit prefix that
        secpol shows, and each subcategory also takes a GUID that works in any
        display language, such as {0CCE923F-69AE-11D9-BED3-505054503030} for
        Credential Validation. On a domain, a GPO that defines advanced auditing
        re-applies its list at each refresh, so set the values there. PowerShell
        7 reads its own key,
        HKLM:\SOFTWARE\Policies\Microsoft\PowerShellCore\ScriptBlockLogging, and
        logs to PowerShellCore/Operational.
  ALSO: Execution policy is a safety setting rather than a security boundary:
        anyone can bypass it, so script block logging (4104) is what records the
        script that ran.

[A-09] Defender beyond on: exclusions, PUA, cloud, ASR
  AREA: Malware defenses (CIS Control 10)
  PS> Get-MpPreference | Select-Object ExclusionPath,ExclusionProcess,ExclusionExtension
  PS> Remove-MpPreference -ExclusionPath "C:\evil"
  CMD> reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Exclusions" /s
  PS> Get-MpPreference | Select-Object ThreatIDDefaultAction_Ids,ThreatIDDefaultAction_Actions
  PS> Remove-MpPreference -ThreatIDDefaultAction_Ids <id>
  PS> Set-MpPreference -PUAProtection Enabled -MAPSReporting Advanced -SubmitSamplesConsent SendAllSamples
  PS> Add-MpPreference -AttackSurfaceReductionRules_Ids 9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2 -AttackSurfaceReductionRules_Actions Enabled
  PS> Get-MpThreatDetection | Select-Object DomainUser,ProcessName,InitialDetectionTime
  PS> Set-MpPreference -EnableControlledFolderAccess Enabled -EnableNetworkProtection Enabled
  WHY: Attackers rarely turn Defender off; they exclude a folder or allow one
       threat (ThreatIDDefaultAction 6 means Allow). PUA protection catches
       junkware, and the LSASS rule stops mimikatz-class attacks.
  NOTE: An exclusion set by policy returns after Remove-MpPreference: set the
        policy to Not Configured in gpedit.msc (or delete the value under the
        policy key) first, then remove the local one.
  ALSO: Even with real-time protection on, controlled folder access and
        network protection stay off until you set them. The first stops
        ransomware rewriting Documents; the second blocks known-bad domains.

[A-10] Optional capabilities: OpenSSH Server and friends
  AREA: Secure configuration (CIS Control 4)
  PS> Get-WindowsCapability -Online | Where-Object State -eq Installed | Select-Object Name
  PS> Get-Service sshd -ErrorAction SilentlyContinue | Select-Object Status,StartType
  PS> Remove-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  PS> Get-Content C:\ProgramData\ssh\sshd_config
  WHY: Windows 11 ships OpenSSH Server as an installable capability; an attacker
       or careless admin can switch it on. The firewall rule for port 22 then
       quietly allows that second door.
  NOTE: If the brief requires SSH, keep it and harden
        C:\ProgramData\ssh\sshd_config (PasswordAuthentication, AllowUsers, no

[A-11] SMB signing and encryption
  AREA: Secure configuration (CIS Control 4)
  PS> Set-SmbServerConfiguration -RequireSecuritySignature $true -EncryptData $true -Force
  PS> Set-SmbClientConfiguration -RequireSecuritySignature $true -Force
  PS> Set-SmbClientConfiguration -EnableInsecureGuestLogons $false -Force
  PS> Get-SmbServerConfiguration | Select-Object EnableSMB1Protocol,RequireSecuritySignature,EncryptData
  PS> Get-SmbClientConfiguration | Select-Object RequireSecuritySignature,EnableInsecureGuestLogons
  WHY: Required signing kills NTLM relay, the attack that turns one weak host
       into domain admin.
  NOTE: Read the current values before assuming: defaults differ by release
        and edition (see Version notes). On Pro or Enterprise,
        RequireSecuritySignature False or EnableInsecureGuestLogons True is a
        finding to explain.
  ALSO: Home edition accepts insecure guest logons by default, letting a fake
        file server hand this PC files without any sign-in. Set
        EnableInsecureGuestLogons False unless the brief names a guest-only
        NAS.

[A-13] Version notes: Windows 11 26H2
  GUI: Win+R, winver: edition, version (26H2), and OS build
      This page targets Windows 11 26H2 (the 24H2 core). Several defaults changed in recent releases: read the current value instead of assuming.
      Account lockout: new installs of 22H2 and later can start with a lockout policy and Allow Administrator account lockout already set (KB5020282 recommends 10 attempts, 10 minutes, and 10 minutes); upgraded machines and machines patched after setup can start at Never, so read net accounts and set the brief's values either way
      SMB: since 24H2, Pro, Enterprise, and Education require SMB signing in both directions, and Pro blocks insecure guest logons; Home edition leaves signing optional
      Administrator protection (Windows 11 only): TypeOfAdminApprovalMode 2 gives each elevation a separate, temporary admin token; it starts off, needs a restart, and while it is on, ConsentPromptBehaviorEnhancedAdmin decides the prompt (I-03)
      Removed since 24H2: Microsoft Defender Application Guard (and its WDAGUtilityAccount), WMIC (use Get-CimInstance), Windows PowerShell 2.0, NTLMv1
      Home edition: leaves out lusrmgr.msc, secpol.msc, and gpedit.msc; use Settings, net user, or net accounts
  WHY: Every other item holds across releases; release changes live here. Check
       this list before you flag a default as a finding or count a changed
       default as a fix.

[A-14] Windows Installer: AlwaysInstallElevated off
  AREA: Access control (CIS Control 6)
  CMD> reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer
  CMD> reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer
  CMD> reg add HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /t REG_DWORD /d 0 /f
  CMD> reg add HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /t REG_DWORD /d 0 /f
  CMD> reg add HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v EnableUserControl /t REG_DWORD /d 0 /f
  GUI: gpedit.msc, Computer Configuration and User Configuration, Administrative Templates, Windows Components, Windows Installer: Always install with elevated privileges = Disabled
  WHY: AlwaysInstallElevated at 1 in both HKLM and HKCU runs any user's .msi as
       SYSTEM: a one-step privilege escalation Microsoft strongly discourages.
       EnableUserControl 0 keeps install options with administrators.
  NOTE: HKCU covers only the signed-in user. Check each profile the brief
        keeps: sign in as that user, or read
        HKEY_USERS\<SID>\SOFTWARE\Policies\Microsoft\Windows\Installer; reg
        add creates missing keys and keeps existing values.

[A-15] Encryption, boot integrity, and recovery: BitLocker, TPM, Secure Boot, and an image backup
  AREA: Data protection (CIS Control 3)
  GUI: msinfo32, System Summary: BIOS Mode UEFI and Secure Boot State On; tpm.msc: Specification Version 2.0
  PS> Confirm-SecureBootUEFI
  PS> Get-Tpm
  PS> Get-BitLockerVolume
  CMD> manage-bde -status
  PS> Resume-BitLocker -MountPoint C:   (turns suspended protection back on)
  PS> Add-BitLockerKeyProtector -MountPoint C: -RecoveryPasswordProtector   (before you encrypt: the 48-digit recovery password)
  PS> Enable-BitLocker -MountPoint C: -TpmProtector   (then encrypt a FullyDecrypted drive)
  PS> Backup-BitLockerKeyProtector -MountPoint C: -KeyProtectorId <id>   (domain-joined: copies the recovery password to Active Directory)
  PS> BackupToAAD-BitLockerKeyProtector -MountPoint C: -KeyProtectorId <id>   (Microsoft Entra joined)
  CMD> wbadmin start backup -backupTarget:E: -include:C: -allCritical -quiet
  WHY: A stolen disk reads in full on another computer unless BitLocker encrypts
       it, and a TPM with Secure Boot keeps the unlock tied to an untampered
       boot.
  NOTE: Save the recovery password away from the machine before you encrypt.
        Suspend-BitLocker pauses protection for firmware updates;
        Resume-BitLocker turns it back on.
  ALSO: BitLocker management needs Pro, Enterprise, or Education; Home offers
        Device encryption in Settings on supported hardware. wbadmin backs up C:
        and everything a bare-metal restore needs to drive E:.

------------------------------ FIX OR BREAK? (practice cards) ------------------
  Brief: Authorized administrators: alice. Authorized users: bob, carol.
  Action: Remove bob from the Administrators group.
  Call: FIX. Bob is a standard user per the brief. Demoting that account is
             least privilege.

  Brief: The company depends on this machine's FTP server for client uploads.
  Action: Stop and disable the FTP service because FTP is insecure.
  Call: BREAKS IT. Required services must stay up. Harden FTP (no anonymous,
                   strong passwords, firewall rule) instead of killing it.

  Brief: Investigation 1: what is the MD5 hash of C:\Users\Public\secret.mp3?
  Action: Delete every media file on the machine first, then start the
          investigation questions.
  Call: CHECK FIRST. Answer the investigation question before you destroy the
                     evidence. Evidence first, fixes second.

  Brief: You log in as alice. Alice is an authorized administrator.
  Action: Change the password of every user including alice to a strong one.
  Call: CHECK FIRST. Changing the sign-in account's password is usually fine but
                     can lock you out if it is recorded wrong; the brief
                     decides. Record every password you set.

  Brief: Nothing in the brief mentions the backup agent installed under
         C:\Program Files\BackupAgent.
  Action: Delete C:\Program Files\BackupAgent because it looks like unknown
          software.
  Call: CHECK FIRST. Unrecognized software is distinct from unauthorized
                     software. Check the publisher, the service that runs it,
                     and its scheduled tasks, then ask the owner before removing
                     a backup or monitoring agent.

  Brief: Remote Desktop must remain available for the helpdesk.
  Action: Set fDenyTSConnections to 1.
  Call: BREAKS IT. That disables RDP. Keep it, require Network Level
                   Authentication, and audit the Remote Desktop Users group
                   instead.

  Brief: No media files are allowed on company computers.
  Action: Delete C:\Users\bob\Music\mixtape.mp3 after confirming no
          investigation question refers to it.
  Call: FIX. Policy violation plus confirmation that it is not evidence. Note
             the path in your change log.

  Brief: The company runs an IIS web server on this host.
  Action: Run Disable-WindowsOptionalFeature for the IIS-WebServer feature to
          shrink attack surface.
  Call: BREAKS IT. Required service. Harden IIS (authentication, directory
                   browsing, updates) rather than removing it.

  Brief: Auditing must be enabled per company policy.
  Action: Run auditpol /clear to start from a clean baseline.
  Call: BREAKS IT. That removes all auditing. Set categories or subcategories to
                   Success and Failure instead.

  Brief: The company handles customer PII; nothing is said about screen locks.
  Action: Set a password-protected screen saver with a 10 minute timeout.
  Call: FIX. Standard policy for any machine that touches PII, and a CIS
             Benchmark recommendation for Windows desktops.

  Brief: IT administers this laptop remotely over SSH.
  Action: Run Remove-WindowsCapability for OpenSSH.Server.
  Call: BREAKS IT. Required service. Keep it, harden sshd_config, and restrict
                   the firewall rule to the admin subnet.

  Brief: Admins on 10.0.20.0/24 need Remote Desktop to this PC.
  Action: Set the Remote Desktop firewall rule's RemoteAddress to 10.0.20.0/24.
  Call: FIX. RDP stays available to the admins who need it, and every other
             address meets the default inbound block.

  Brief: Staff save scans to an old NAS that the business requires, and its SMB
         signing support still awaits confirmation. On this PC,
         Get-SmbClientConfiguration shows RequireSecuritySignature False.
  Action: Run Set-SmbClientConfiguration -RequireSecuritySignature $true right
          away.
  Call: CHECK FIRST. Required signing stops an attacker in the middle from
                     tampering with or hijacking this PC's SMB sessions, and
                     24H2 Pro, Enterprise, and Education require it by default.
                     A NAS without signing support loses its connection: confirm
                     its support first (a firmware update often adds it), then
                     require signing.

  Brief: Staff clock in at http://timeclock.honua.example, a required site that
         has only plain HTTP.
  Action: Force HTTPS-Only in every browser for every site, the time clock
          included.
  Call: CHECK FIRST. HTTPS-Only would block the required time clock. Add the
                     host as an exception first (HttpAllowlist in Chrome, Manage
                     Exceptions in Firefox), then force it for everything else.

  Brief: The brief requires the intranet site at intranet.honua.example. It
         stopped loading after this morning's hardening.
  Action: Undo every change from this morning until the site loads again.
  Call: CHECK FIRST. Find the broken link first: ipconfig /all, ping the
                     gateway, nslookup the name, then Test-NetConnection
                     intranet.honua.example -Port 443. Your change log then
                     points to the one change to undo.

  Brief: The brief requires BitLocker on this PC's C: drive. Get-BitLockerVolume
         shows C: FullyDecrypted with an empty KeyProtector list.
  Action: Run Add-BitLockerKeyProtector -MountPoint C:
          -RecoveryPasswordProtector, save the recovery password off this PC,
          then run Enable-BitLocker -MountPoint C: -TpmProtector.
  Call: FIX. That is the safe order: the recovery password exists, and sits away
             from the PC, before encryption starts, so a TPM change after a
             firmware update still leaves a way back in.

------------------------------ SPOT THE FINDING (output snippets) --------------
  Output of net accounts. Tap the line that is the finding.
     Minimum password length:                 12
     Maximum password age (days):             60
  >> Lockout threshold:                       Never
     Length of password history maintained:   24
  WHY: Lockout threshold Never means unlimited password guesses. Set it to 5
       with net accounts /lockoutthreshold:5.

  Get-NetFirewallProfile output. Tap the finding.
     Domain    True
     Private   True
  >> Public    False
     DefaultInboundAction  Block
  WHY: The Public profile is off. A common misconfiguration leaves exactly one
       profile disabled.

  Get-LocalUser output. Tap the finding.
     alice   True   PasswordRequired: True
     bob     True   PasswordRequired: True
  >> svc_backup  True   PasswordRequired: False
     Guest   False  PasswordRequired: False
  WHY: An enabled account with PasswordRequired False is allowed a blank
       password: set one and require it (net user svc_backup /passwordreq:yes).
       Guest is disabled, so it is fine for now.

  Today is 10/19/2026. Status lines gathered from this PC. Tap the finding.
     Get-Service wuauserv:    Running   Automatic
  >> Newest Get-HotFix:       Security Update   InstalledOn 5/14/2026
     Defender signatures:     10/19/2026
     Firewall, all profiles:  Enabled True
  WHY: The newest update is five months old: updates stopped even though the
       service runs. Open Settings, Windows Update: resume updates if they are
       paused, check for updates, and install them. Defender signatures update
       on their own schedule, so their date speaks for Defender alone.

  netstat -abno output. Tap the finding.
     TCP    0.0.0.0:135    LISTENING   [svchost.exe]
     TCP    0.0.0.0:445    LISTENING   System
  >> TCP    0.0.0.0:4444   LISTENING   [nc.exe]

  WHY: A netcat listener on 4444 is a backdoor. Find its PID, its path, and
       whatever task or Run key starts it.

     EnableLUA                  : 1
  >> ConsentPromptBehaviorAdmin : 0
     PromptOnSecureDesktop      : 1
     FilterAdministratorToken   : 1
  WHY: ConsentPromptBehaviorAdmin 0 lets admins elevate silently. Set 2 (Always
       notify) or 5, the default; with PromptOnSecureDesktop 1, both prompt on
       the secure desktop.

  Get-Content of the hosts file. The brief names the intranet server at 10.0.0.5. Tap the finding.
     127.0.0.1       localhost
     ::1             localhost
  >> 127.0.0.1       update.antivirus-vendor.example
     10.0.0.5        intranet.example.com
  WHY: This line points the antivirus update site at this PC itself, so every
       update check fails and signatures go stale. Remove it. The intranet line
       matches the brief, so it stays.

     PUAProtection          : 1
  >> ExclusionPath          : {C:\Users\Public\Libraries}
     DisableRealtimeMonitoring : False
     MAPSReporting          : 2
  WHY: An exclusion on a Public folder is how malware hides from a running
       Defender. Remove it with Remove-MpPreference.

  Registry values under HKLM:\SYSTEM\CurrentControlSet\Control\Lsa. Tap the finding.
     RestrictAnonymous      : 1
     NoLMHash               : 1
  >> LmCompatibilityLevel   : 0
     LimitBlankPasswordUse  : 1
  WHY: LmCompatibilityLevel 0 sends LM and NTLMv1 responses, which crack in
       minutes. Set it to 5. Check the level on older releases and mixed
       domains; Windows 11 24H2 and Windows Server 2025 remove NTLMv1.

  reg query of the Windows Update policy keys. The brief says this PC updates straight from Microsoft. Tap the finding.
     NoAutoUpdate          REG_DWORD    0x0
     AUOptions             REG_DWORD    0x4
  >> UseWUServer           REG_DWORD    0x1
     ScheduledInstallDay   REG_DWORD    0x0
  WHY: UseWUServer 1 sends every update check to the WUServer address instead of
       Microsoft, while the brief says updates come straight from Microsoft, so

     C$        C:\            Default share

     ADMIN$    C:\Windows     Remote Admin

  WHY: A $ hides a share from browsing and keeps it reachable. tools$ is an
       added share on a folder every user can write to: record it, then
       Remove-SmbShare -Name tools$ -Force when the brief leaves it out. The

     ...\Windows\WindowsUpdate\AU    AUOptions            REG_DWORD    0x4

  WHY: DisableAntiSpyware 1 is the Turn off Microsoft Defender Antivirus policy,

  WHY: ProtectionStatus Off on a FullyEncrypted drive means protection is

  WHY: A 169.254.x.x address means the DHCP request went unanswered, so this PC

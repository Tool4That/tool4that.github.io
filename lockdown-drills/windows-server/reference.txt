================================================================================
 02: WINDOWS SERVER HARDENING: SOLUTION WALKTHROUGH
     Windows Server 2025 (member server or domain controller)
 Training reference for virtual machines you own or are authorized to change.
 Three levels: L1 Doorman, L2 Watchman, L3 Hunter. Every item = COMMAND, WHY,
 NOTE, and the hardening AREA it belongs to. No scripts by design: type it,
 read it, explain it. Item IDs match the Lockdown Drills trainer for this OS.
 Unofficial practice; not affiliated with or endorsed by Microsoft.

 COMMAND LEGEND: PS> runs in an elevated PowerShell and CMD> in an elevated
 Command Prompt. Type what follows the prefix, and replace each value in angle
 brackets, such as <name>, with a real one. GUI: lines walk through a window,
 and indented lines show values to set or read.

 HARDENING AREAS (CIS Critical Security Controls v8)
   Account management ........ CIS Control 5
   Access control ............ CIS Control 6
   Secure configuration ...... CIS Control 4 (software inventory: Control 2)
   Patching .................. CIS Control 7
   Malware defenses .......... CIS Control 10
   Audit logging ............. CIS Control 8
   Also tagged: Data protection (CIS Control 3); Investigation (forensics
   basics: answer questions and preserve evidence before you change things).
================================================================================

------------------------------ DOORMAN -----------------------------------------
 Lock the doors. First find out what the box is (standalone, member server, or
 domain controller), then users, admins, passwords, and policy in the place that
 actually takes effect: local, or the domain. Learn it first: Defense Ladder s2,
 "Desktop, member server, or domain controller."
 https://freeapp4that.store/defense-ladder/#sophomore/s2
--------------------------------------------------------------------------------
[B-00] Scenario brief and evidence first
  AREA: Investigation (forensics basics)
  GUI: open the scenario brief (the documented requirements for this machine) and write down authorized users, admins, required services, and anything forbidden
  PS> (Get-CimInstance Win32_ComputerSystem).DomainRole
      0-1 standalone or member workstation, 2-3 standalone or member server, 4-5 domain controller
  PS> Get-WindowsFeature AD-Domain-Services,DNS,DHCP,Web-Server,Web-Ftp-Server | Select-Object Name,Installed
  WHY: Most outages during hardening come from acting against the documented
       requirements: removing a user, role, or service the business needs is an
       availability failure. Evidence first: answer the investigation questions
       before any change (Defense Ladder f1). Which commands apply depends on
       the role: local accounts and secpol on a member server, Active Directory
       and Group Policy on a domain controller.
  NOTE: Unfamiliar is distinct from unauthorized: find what starts it, who owns
        it, and what it does, then ask the owner before removing an agent
        (Defense Ladder s1).

[B-01] List users: local and domain
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Select-Object Name,Enabled,PasswordRequired,LastLogon
  PS> Get-ADUser -Filter * -Properties Enabled,PasswordNeverExpires,PasswordNotRequired,LastLogonDate | Select-Object Name,Enabled,PasswordNeverExpires,PasswordNotRequired,LastLogonDate
  CMD> net user /domain
  GUI: dsa.msc (Active Directory Users and Computers) on a DC; lusrmgr.msc on a member server
  WHY: Unauthorized accounts are backdoors. On a DC the local SAM is gone; every
       account is a domain account, so Get-ADUser is the list to compare with
       the brief.
  NOTE: PasswordNotRequired=True and PasswordNeverExpires=True are findings in
        their own right.

[B-02] Remove or disable an unauthorized user
  AREA: Account management (CIS Control 5)
  PS> Get-ScheduledTask | Where-Object { $_.Principal.UserId -like '*baduser' } | Select-Object TaskPath,TaskName
  PS> Get-CimInstance Win32_Service | Where-Object StartName -like '*baduser' | Select-Object Name,StartName,PathName
  PS> Disable-ADAccount -Identity baduser
  PS> Remove-ADUser -Identity baduser -Confirm:$false
  PS> Remove-LocalUser -Name "baduser"
  CMD> net user baduser /delete
  WHY: Disable first if the brief is unclear, delete when it is not: a disabled
       account keeps its SID and group memberships for the investigation
       question.
  NOTE: Answer every investigation question that names the account first, and
        handle each task or service the first two lines show running as it.
        Deleting the account keeps its profile folder under C:\Users: search it
        for evidence and prohibited files before you remove the folder.

[B-03] Audit the privileged groups
  AREA: Account management (CIS Control 5)
  PS> Get-ADGroupMember "Domain Admins"; Get-ADGroupMember "Enterprise Admins"; Get-ADGroupMember "Schema Admins"; Get-ADGroupMember "Administrators"
  PS> Get-ADGroupMember "Account Operators"; Get-ADGroupMember "Server Operators"; Get-ADGroupMember "Backup Operators"; Get-ADGroupMember "DnsAdmins"
  PS> Remove-ADGroupMember -Identity "Domain Admins" -Members baduser -Confirm:$false
  PS> Get-LocalGroupMember -Group Administrators
  CMD> net localgroup Administrators baduser /delete
  WHY: Domain Admins is the whole game, and the operator groups, Backup
       Operators, and DnsAdmins are quieter roads to the same place. On a member
       server it is still the local Administrators group.

[B-04] Disable Guest; protect the built-in Administrator
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Where-Object { $_.SID -like '*-50[01]' } | Select-Object Name,Enabled,SID   (member server)
  PS> Get-ADUser -Filter * | Where-Object { $_.SID -like '*-50[01]' } | Select-Object Name,Enabled,SID   (domain controller)
  CMD> whoami /user
  CMD> net user Guest /active:no
  PS> Disable-ADAccount -Identity Guest
  CMD> net user Administrator /active:no
  PS> Set-ADUser -Identity Administrator -PasswordNeverExpires $false
  WHY: Well-known accounts are brute-forced by name. The domain Guest should
       always be disabled; the domain Administrator stays enabled only if the
       brief uses it, with a strong password. The built-in Administrator's SID
       ends in -500 and Guest's in -501, so the first lines find both even after
       a rename.
  NOTE: Keep the account the brief tells you to log in with enabled. whoami
        /user shows your own SID: one ending in -500 is the built-in
        Administrator. Rename both accounts as a last step, and only when the
        brief or policy asks (Rename-LocalUser on a member server); the SID
        stays, so disabling and a strong password carry the protection.

[B-05] Strong passwords and forced change
  AREA: Account management (CIS Control 5)
  PS> Get-ADUser -Filter * -Properties PasswordLastSet,PasswordNeverExpires | Select-Object Name,Enabled,PasswordLastSet,PasswordNeverExpires
  PS> Set-ADAccountPassword -Identity alice -Reset -NewPassword (Read-Host -AsSecureString 'New password')
  PS> Set-ADUser -Identity alice -PasswordNeverExpires $false -PasswordNotRequired $false
  PS> Set-ADUser -Identity alice -ChangePasswordAtLogon $true
  PS> Get-ADUser -Identity alice -Properties PasswordNeverExpires,pwdLastSet | Select-Object Name,PasswordNeverExpires,pwdLastSet
  PS> Get-ADUser -Filter 'Enabled -eq $true' | Where-Object SamAccountName -ne $env:USERNAME | Set-ADUser -PasswordNeverExpires $false
  CMD> net user alice *
  CMD> net user alice /logonpasswordchg:yes
  WHY: Weak, shared, or blank passwords are the way in. PasswordNotRequired lets
       an account have a blank password even when policy forbids it;
       PasswordNeverExpires defeats the aging policy. Clear the flags in one
       Set-ADUser call and ask for a change in the next, and pwdLastSet 0
       confirms the change at next sign-in.
  NOTE: Set the domain password policy first (B-06, B-07), so every new password
        meets it. Read-Host and net user * prompt for the password, which keeps
        it out of the command history. The bulk line also reaches service
        accounts: handle those in A-10, where the service gets its new password
        at the same time, or filter them out by name. Record every changed
        password somewhere safe (on paper, in a lab).

[B-06] Password policy where it actually lives
  AREA: Account management (CIS Control 5)
  PS> Get-ADDefaultDomainPasswordPolicy
  PS> Set-ADDefaultDomainPasswordPolicy -Identity (Get-ADDomain).DNSRoot -MinPasswordLength 12 -ComplexityEnabled $true -PasswordHistoryCount 24 -MinPasswordAge 1.00:00:00 -MaxPasswordAge 60.00:00:00 -ReversibleEncryptionEnabled $false
  GUI: gpmc.msc, Default Domain Policy, Computer Configuration, Policies, Windows Settings, Security Settings, Account Policies, Password Policy
  CMD> net accounts /minpwlen:12 /maxpwage:60 /minpwage:1 /uniquepw:24   (member server)
  GUI: secpol.msc, Account Policies, Password Policy (member server)
  WHY: On a domain controller, net accounts and secpol.msc are overridden by the
       Default Domain Policy, so a change there never sticks. On a member server
       the local policy is the one that counts. Turning reversible encryption
       off protects new passwords only, so reset the passwords set while it was
       on; Active Directory also keeps a per-account flag (Get-ADUser <name>
       -Properties AllowReversiblePasswordEncryption).
  NOTE: The scenario brief sets the numbers; these commands show one sample
        brief. The CIS Benchmark asks for 14 or more characters, a history of 24
        or more, a maximum age of 365 days or fewer (and above 0), and a minimum
        age of 1 day or more. Defense Ladder s2 compares the CIS and NIST
        rulebooks.

[B-07] Account lockout policy
  AREA: Account management (CIS Control 5)
  PS> Set-ADDefaultDomainPasswordPolicy -Identity (Get-ADDomain).DNSRoot -LockoutThreshold 5 -LockoutDuration 00:30:00 -LockoutObservationWindow 00:30:00
  CMD> net accounts /lockoutthreshold:5 /lockoutduration:30 /lockoutwindow:30   (member server)
  PS> Search-ADAccount -LockedOut | Select-Object Name
  PS> Unlock-ADAccount -Identity alice
  WHY: Turns an online brute force from thousands of guesses a minute into five
       per half hour. Search-ADAccount shows who is locked out right now, which
       is also an investigation clue.
  NOTE: The scenario brief sets the numbers; these commands show one sample
        brief. The CIS Benchmark asks for a threshold of 5 or fewer (and above
        0) and a lockout duration and reset window of 15 minutes or more.
        Defense Ladder s2 compares the CIS and NIST rulebooks. Lockout covers
        the local built-in Administrator of a member server only when Allow
        Administrator account lockout is Enabled (AllowAdministratorLockout = 1
        in a secedit template, Hunter A-01); it then locks that account for
        network sign-ins such as Remote Desktop, and console sign-in stays
        available.

[B-08] Firewall on for all profiles
  AREA: Secure configuration (CIS Control 4)
  PS> Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True
  PS> Get-NetFirewallProfile -PolicyStore ActiveStore | Select-Object Name,Enabled,DefaultInboundAction
  CMD> netsh advfirewall set allprofiles state on
  GUI: Settings, Privacy and security, Windows Security, Firewall and network
       protection.
  WHY: Default-deny inbound covers the service you have not found yet.
       Misconfigured machines often have exactly one profile off, usually
       Public.
  NOTE: DefaultInboundAction should be Block. ActiveStore shows the values in
        force, Group Policy included; the plain view shows NotConfigured for a
        value left at its Windows default (Block for inbound). Allow-rule review
        is a Watchman item.

[B-09] Windows Update on a server
  AREA: Patching (CIS Control 7)
  CMD> sconfig   (option 5: Update setting = Automatic; option 6: Install Updates)
  GUI: Settings, Windows Update, Check for updates
  PS> Set-Service -Name wuauserv -StartupType Automatic; Start-Service wuauserv
  PS> Get-Service wuauserv,BITS,UsoSvc | Select-Object Name,Status,StartType
  CMD> reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate /s
  GUI: gpmc.msc (or gpedit.msc), Computer Configuration, Policies, Administrative Templates, Windows Components, Windows Update: Configure Automatic Updates = Enabled (4)
  WHY: Patching closes the holes scanners find, and the automatic-update setting
       matters on its own. On a server, policy usually decides it, so check the
       GPO when the setting will not stick. UseWUServer 1 sends every update
       check to the WUServer address, which is normal only when the brief names
       an update server, and NoAutoUpdate 1 turns automatic updates off.
  NOTE: Start updates first and let them run; after each restart, check again
        until Windows Update reports this server is up to date. Manual is the
        shipped start type for wuauserv (it starts on demand); Disabled is the
        finding. Save work before any reboot.

[B-10] Microsoft Defender on Server
  AREA: Malware defenses (CIS Control 10)
  PS> Get-MpComputerStatus | Select-Object AMServiceEnabled,RealTimeProtectionEnabled,AntivirusSignatureLastUpdated
  PS> Get-MpComputerStatus | Select-Object AMRunningMode
  PS> Install-WindowsFeature -Name Windows-Defender
  PS> Set-MpPreference -DisableRealtimeMonitoring $false
  PS> Update-MpSignature
  PS> Start-MpScan -ScanType QuickScan
  PS> Start-MpScan -ScanType CustomScan -ScanPath C:\Users
  PS> Get-MpThreatDetection | Select-Object InitialDetectionTime,ProcessName,Resources
  GUI: Windows Security, Virus and threat protection, Manage settings
  WHY: Windows Server ships with Defender, but someone can remove the feature or
       disable it by policy. Real-time protection and current signatures both
       matter.
  NOTE: If Get-MpComputerStatus errors, the feature is missing: install it,
        restart when RestartNeeded says Yes, then configure it. AMRunningMode
        Normal means active; Passive means an administrator set it beside
        another antivirus, and the brief decides which product protects the
        server. Answer the investigation questions before any scan, and record
        each detection's Resources path before removing the program that dropped
        it.

[B-11] Remove unapproved software
  AREA: Secure configuration: software (CIS Controls 2 and 4)
  PS> Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*, HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*, Registry::HKEY_USERS\*\Software\Microsoft\Windows\CurrentVersion\Uninstall\* -ErrorAction SilentlyContinue | Select-Object DisplayName,DisplayVersion,Publisher,UninstallString | Sort-Object DisplayName
  GUI: Settings, Apps, Installed apps (or appwiz.cpl)
  WHY: Hacking tools, games, torrent clients, and remote-access tools are
       acceptable-use violations and attack surface.
  NOTE: Software the brief requires stays. The registry listing is instant;
        Win32_Product is slow and can trigger repairs. HKEY_USERS adds apps
        installed for one signed-in user only. Capture tools install Npcap as a
        program of its own: remove it too when the brief leaves out packet
        capture. After removing a remote-access tool, look for its leftover
        service (I-04) and firewall rule (I-12). Portable tools appear only in a
        file search (B-12, A-06).

[B-12] Find unapproved media and loose executables
  AREA: Data protection (CIS Control 3)
  PS> Get-ChildItem -Path C:\Users,C:\inetpub,C:\Shares -Recurse -Force -File -Include *.mp3,*.mp4,*.wav,*.avi,*.mkv,*.flac,*.mov,*.m4a,*.mpg,*.mpeg,*.ogg,*.flv,*.wma,*.aac -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\|^C:\\Users\\(All Users|Default User)\\' | Select-Object FullName
  PS> Get-ChildItem -Path C:\Users,C:\inetpub -Recurse -Force -File -Include *.exe,*.bat,*.cmd,*.ps1,*.vbs,*.hta,*.aspx,*.py,*.jar,*.zip,*.7z,*.rar -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\Local\\(Microsoft|Packages)\\|^C:\\Users\\(All Users|Default User)\\' | Select-Object FullName,LastWriteTime
  CMD> tar -tf "C:\Users\<user>\Downloads\<archive>.zip"
  WHY: Media in user profiles and web roots is the usual acceptable-use
       violation; a stray .aspx or .ps1 under inetpub is a webshell.
  NOTE: Confirm against the brief before deleting, and search C:\ too, beyond
        C:\Users. -Force shows hidden files, and the filters skip app caches
        under AppData and the All Users and Default User links. Answer every
        investigation question that names a file first and record its hash
        (B-14); then delete it and note the path in your change log. tar -tf
        lists what a .zip holds before you delete it. Python and other runtimes
        stay when the brief needs them.

[B-13] Stop obviously unsafe services
  AREA: Secure configuration (CIS Control 4)
  PS> Get-Service -Name ftpsvc,TermService,RemoteRegistry,SNMP -ErrorAction SilentlyContinue | Select-Object Name,Status,StartType
  PS> Stop-Service -Name RemoteRegistry; Set-Service -Name RemoteRegistry -StartupType Disabled
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 1
  PS> Get-NetFirewallRule -Group '@FirewallAPI.dll,-28752' -ErrorAction SilentlyContinue | Disable-NetFirewallRule
  CMD> reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services" /v fDenyTSConnections
  PS> Get-WindowsFeature Remote-Assistance
  GUI: services.msc, Startup type Disabled; Settings, System, Remote Desktop
  PS> Stop-Service -Name Spooler; Set-Service -Name Spooler -StartupType Disabled   (unless this is the print server)
  PS> Get-NetTCPConnection -State Listen -LocalPort 21,3389 -ErrorAction SilentlyContinue
  WHY: Telnet and FTP leak credentials in cleartext. Remote Registry lets a
       remote attacker edit the registry. RDP is a brute-force magnet. The Print
       Spooler on a domain controller is PrintNightmare: off unless the brief
       makes it a print server.
  NOTE: If the brief requires RDP, FTP, or SSH, harden it instead of killing it
        (I-11). Remote management tools use Remote Registry on a server: disable
        it when the brief names local administration only, and record the
        change. Turning Remote Desktop off takes the setting plus its firewall
        group (the @FirewallAPI name works in any display language).
        fDenyTSConnections 0 under the Terminal Services policy key forces
        Remote Desktop back on, so an error that the value is missing is the
        good result. When the brief leaves Remote Assistance out, run Uninstall-
        WindowsFeature Remote-Assistance. The last line returns empty once FTP
        and Remote Desktop stop listening.

[B-14] Hash a file for an investigation question
  AREA: Investigation (forensics basics)
  PS> Get-FileHash -LiteralPath 'C:\Users\<user>\Desktop\<file>' -Algorithm SHA256 | Format-List
  CMD> certutil -hashfile "C:\Users\<user>\Desktop\<file>" SHA256
  PS> Get-MpThreatDetection | Select-Object InitialDetectionTime,Resources
  WHY: An investigation answer is the exact hex string for the exact algorithm
       the question names. Hash the untouched file before any Defender scan,
       cleanup, or move, because a changed or quarantined file gives a different
       answer or vanishes.
  NOTE: Hash lengths: MD5 32 hex characters, SHA1 40, SHA256 64, and the value
        repeats on every run. -LiteralPath reads names with [ ] that -Path
        skips, and quotes keep paths with spaces whole. certutil defaults to
        SHA1, so name the algorithm. When opening the file reports a virus,
        Defender has already quarantined it: Get-MpThreatDetection and Windows
        Security, Protection history show the path and time to record.

[B-15] Create the users and groups the brief lists
  AREA: Account management (CIS Control 5)
  PS> New-ADUser -Name 'kekoa' -SamAccountName 'kekoa' -AccountPassword (Read-Host -AsSecureString 'Password') -Enabled $true
  PS> New-ADGroup -Name 'Accounting' -GroupScope Global
  PS> Add-ADGroupMember -Identity 'Accounting' -Members kekoa
  PS> Get-ADGroupMember -Identity 'Accounting'
  CMD> net user kekoa * /add   (member server)
  CMD> net localgroup Accounting /add   (member server)
  CMD> net localgroup Accounting kekoa /add   (member server)
  WHY: A user or group the brief lists and the machine lacks leaves a person
       unable to sign in or reach the files the job needs. Creating exactly what
       the brief lists keeps the account list matching the source of truth.
  NOTE: Create only the accounts and groups the brief lists, then add the
        members it names, and read the result back. Read-Host and net user *
        prompt for the password, so it stays out of the command history.
        Security events 4720 (account created) and 4728 (added to a global
        group) record each step.

[B-16] Find files that store passwords
  AREA: Data protection (CIS Control 3)
  PS> Get-ChildItem -Path C:\Users,C:\inetpub,C:\Shares -Recurse -Force -File -Include *.txt,*.csv,*.ini,*.xml,*.log,*.ps1,*.bat -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\Local\\|^C:\\Users\\(All Users|Default User)\\' | Select-String -Pattern 'passw(or)?d|pwd|credential' -List | Select-Object Path,LineNumber,Line
  CMD> findstr /s /i /m /c:"password" C:\Users\*.txt C:\Users\*.csv C:\Users\*.ini
  PS> Get-ChildItem -Path C:\Users\*\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt -Force -ErrorAction SilentlyContinue | Select-String -Pattern 'net user|ConvertTo-SecureString|passw' | Select-Object Path,Line
  PS> Get-ChildItem -Path C:\Windows\Panther\Unattend.xml,C:\Windows\Panther\Unattend\Unattend.xml,C:\Windows\System32\Sysprep\unattend.xml -Force -ErrorAction SilentlyContinue | Select-String -Pattern '<Password>|AdministratorPassword' | Select-Object Path,LineNumber
  CMD> cmdkey /list
  WHY: A password saved in a note, a script, the PowerShell history, or a
       leftover Windows Setup answer file hands an account to anyone who reads
       it. Searching by content finds them under any file name.
  NOTE: Answer any investigation question that names the file first and record
        its hash (B-14); then remove the file or move it where the brief says,
        and note the path in your change log. Review each hit, since license and
        app files match too. An answer file's hidden password is only encoded,
        so treat it as plain text. cmdkey /list shows the passwords Windows
        saved for the signed-in user, such as TERMSRV/<host> for a Remote
        Desktop sign-in; cmdkey /delete:<target> removes one the brief leaves
        out, and each user reads only their own list.

------------------------------ WATCHMAN ----------------------------------------
 Check the windows. Roles and features, audit and policy through Group Policy,
 services, shares, tasks, ports, logs, and the required roles (IIS, FTP, DNS,
 and DHCP) hardened instead of removed. Learn it first: Defense Ladder j1,
 "Windows Server and Active Directory," and Defense Ladder j2, "Group Policy."
 https://freeapp4that.store/defense-ladder/#junior/j1
 https://freeapp4that.store/defense-ladder/#junior/j2

[I-01] Audit policy: turn the lights on
  AREA: Audit logging (CIS Control 8)
  CMD> wevtutil sl Security /ms:201326592
  CMD> auditpol /backup /file:C:\Windows\Temp\audit-before.csv
  CMD> auditpol /set /category:* /success:enable /failure:enable
  CMD> auditpol /get /category:*
  GUI: gpmc.msc, Default Domain Controllers Policy, Computer Configuration, Policies, Windows Settings, Security Settings, Advanced Audit Policy Configuration
  WHY: Without auditing, Event Viewer has nothing to tell you or an
       investigator. Logon, account management, and policy change are the key
       ones.
  NOTE: On a DC the Default Domain Controllers Policy overrides local auditpol;
        set it there or it will revert at the next gpupdate. Use one route:
        auditpol here, or Advanced Audit Policy Configuration in Group Policy,
        and leave secpol's basic Audit Policy node unset, because Microsoft
        warns that mixing the two gives unexpected results; trust auditpol /get.
        The wevtutil line raises the Security log to 192 MB first, so the extra
        events keep older evidence, and auditpol /restore
        /file:C:\Windows\Temp\audit-before.csv undoes the change. Fine-grained
        subcategories, and trimming the noisiest ones, are a Hunter item (A-08).

[I-02] Security Options in secpol.msc
  AREA: Secure configuration (CIS Control 4)
  GUI: secpol.msc, Local Policies, Security Options
      Accounts: Limit local account use of blank passwords to console logon only = Enabled
      Devices: Prevent users from installing printer drivers = Enabled
      Interactive logon: Don't display last signed-in = Enabled (older label: Do not display last user name)
      Interactive logon: Machine inactivity limit = 900 seconds or fewer
      Interactive logon: Do not require CTRL+ALT+DEL = Disabled
      Network access: Do not allow anonymous enumeration of SAM accounts and shares = Enabled
      Network security: LAN Manager authentication level = Send NTLMv2 response only. Refuse LM & NTLM
      Microsoft network client and server: Digitally sign communications (always) = Enabled
      Shutdown: Allow system to be shut down without having to log on = Disabled
      User Account Control: Run all administrators in Admin Approval Mode = Enabled
      Domain controller: LDAP server signing requirements = Require signing
      Domain member: Digitally encrypt or sign secure channel data (always) = Enabled
  WHY: These are the classic CIS and STIG level-one settings; each blocks a
       named attack: blank-password remote logon, username harvesting, LM and
       NTLMv1 cracking or relay, SMB relay, pre-auth shutdown, and UAC bypass.
       Check the level on older releases and mixed domains; Windows 11 24H2 and
       Windows Server 2025 remove NTLMv1.
  NOTE: Command-line equivalents live in the registry (Hunter A-02) or secedit
        (Hunter A-01). With Do not require CTRL+ALT+DEL Disabled, a VM takes the
        sequence from its window menu or shortcut (Ctrl+Alt+End in Hyper-V and
        Remote Desktop). The machine inactivity limit locks every idle session,
        whoever signed in.

[I-03] UAC to Always notify
  AREA: Secure configuration (CIS Control 4)
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name EnableLUA -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name ConsentPromptBehaviorAdmin -Value 2 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name PromptOnSecureDesktop -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name FilterAdministratorToken -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name ConsentPromptBehaviorUser -Value 0 -Type DWord
  GUI: Control Panel, User Accounts, Change User Account Control settings,
       slider to the top.
  WHY: UAC off means every process an admin runs is full admin with no prompt,
       which malware loves. ConsentPromptBehaviorAdmin 0 elevates silently; 2
       (Always notify) prompts on the secure desktop for every elevation; 5, the
       default, prompts only for programs outside Windows.
       FilterAdministratorToken 1 puts the built-in Administrator account, the
       one most often used on a server, under UAC too.
  NOTE: Changing EnableLUA needs a reboot to fully apply.
        ConsentPromptBehaviorUser 0 refuses elevation from a standard session,
        so admins elevate from their own session. A Security Options policy for
        these values replaces the slider at the next refresh (gpresult /scope
        computer /v shows it).

[I-04] Service audit: what runs, from where
  AREA: Secure configuration (CIS Control 4)
  PS> Get-CimInstance Win32_Service | Select-Object Name,State,StartMode,StartName,PathName | Sort-Object Name
  PS> Get-Service | Where-Object Status -eq Running | Sort-Object DisplayName
  PS> Get-Service -Name EventLog,mpssvc,WinDefend | Select-Object Name,Status,StartType
  PS> Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\SNMP\Parameters\ValidCommunities' -ErrorAction SilentlyContinue
  PS> Stop-Service -Name <name>; Set-Service -Name <name> -StartupType Disabled
  WHY: Look for Telnet, FTP, SNMP, SSDP, UPnP, Remote Registry, Xbox services,
       odd names, and any service whose PathName is under C:\Users or C:\Temp.
       Those are planted. A StartName of LocalSystem means the service runs as
       SYSTEM, the most powerful account on the machine. SNMP answers on 161/udp
       to anyone who knows a community name, and public or private is a guess
       away.
  NOTE: Required services (IIS, DNS, DHCP, OpenSSH, MySQL, Apache) stay running;
        harden their configs instead. The event log, firewall (mpssvc), and
        Defender (WinDefend) services read Running and Automatic; Stopped or
        Disabled on any of them is a finding (WinDefend can sit stopped when the

        the feature: Uninstall-WindowsFeature -Name SNMP-Service.

[I-05] Roles and features: remove what the brief does not need
  AREA: Secure configuration (CIS Control 4)

[I-11] Remote Desktop hardening when RDP is required
  AREA: Access control (CIS Control 6)
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp' -Name UserAuthentication -Value 1
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp' -Name SecurityLayer -Value 2
  PS> $ts='HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services'; if (-not (Test-Path $ts)) { New-Item -Path $ts -Force | Out-Null }
  PS> foreach ($n in 'fDisableCdm','fDisablePNPRedir','fPromptForPassword','fEncryptRPCTraffic') { Set-ItemProperty -Path $ts -Name $n -Value 1 -Type DWord }
  PS> Get-CimInstance -Namespace root\cimv2\TerminalServices -ClassName Win32_TSGeneralSetting | Select-Object TerminalName,UserAuthenticationRequired,PolicySourceUserAuthenticationRequired

  PS> Get-LocalGroupMember -SID S-1-5-32-555
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Remote Assistance' -Name fAllowToGetHelp -Value 0
  PS> Set-NetFirewallRule -DisplayGroup "Remote Desktop" -RemoteAddress <admin subnet>
  WHY: Network Level Authentication forces a login before a session exists,
       which kills pre-auth exploits, and the TLS security layer (SecurityLayer
       2) proves the server is the real one before anyone types a password.

       dropping files on the connecting PC, and prompting at every connection
       defeats a password saved in an .rdp file. Administrators connect whenever
       RDP is on, so the Remote Desktop Users group is the list of non-admins
       the brief names; audit it. Remote Assistance should be off. Scope the
       Remote Desktop firewall rule to the admin subnet that the brief names, so
       only those addresses reach the port.
  NOTE: The redirector service (UmRdpService) stays at Manual while RDP is in
        use; the policy values do the blocking. PolicySource 1 in the read-back
        means Group Policy decides NLA. SecurityLayer 2 uses a self-signed
        certificate unless the brief supplies one, so the first connection shows
        a certificate prompt. -SID S-1-5-32-555 names Remote Desktop Users in
        any display language.

[I-12] Firewall allow-rule review

  WHY: Firewall on means nothing if a rule allows the whole internet into

  NOTE: ActiveStore lists the rules in force, Group Policy rules included. -Name

[A-01] Security policy as a file: secedit
  AREA: Secure configuration (CIS Control 4)
  CMD> secedit /export /cfg C:\Temp\secpol.cfg
      [System Access] MinimumPasswordAge = 1, MaximumPasswordAge = 60, MinimumPasswordLength = 12, PasswordComplexity = 1, PasswordHistorySize = 24, LockoutBadCount = 5, ResetLockoutCount = 30, LockoutDuration = 30, AllowAdministratorLockout = 1, ClearTextPassword = 0, EnableGuestAccount = 0

  CMD> secedit /analyze /db C:\Windows\security\local.sdb /cfg C:\Temp\secpol.cfg

[A-02] LSA and anonymous-access registry hardening
  AREA: Secure configuration (CIS Control 4)
  PS> $lsa='HKLM:\SYSTEM\CurrentControlSet\Control\Lsa'
  PS> Set-ItemProperty -Path $lsa -Name LimitBlankPasswordUse -Value 1 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name RestrictAnonymous -Value 1 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name RestrictAnonymousSAM -Value 1 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name NoLMHash -Value 1 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name LmCompatibilityLevel -Value 5 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name EveryoneIncludesAnonymous -Value 0 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name ForceGuest -Value 0 -Type DWord
  PS> Set-ItemProperty -Path $lsa -Name RestrictRemoteSAM -Value 'O:BAG:BAD:(A;;RC;;;BA)' -Type String   (member server)
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name allownullsessionfallback -Value 0 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name NTLMMinClientSec -Value 537395200 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name NTLMMinServerSec -Value 537395200 -Type DWord
  PS> Get-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name LocalAccountTokenFilterPolicy -ErrorAction SilentlyContinue
  PS> Remove-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name LocalAccountTokenFilterPolicy
  WHY: Null-session enumeration (RestrictAnonymous), LM hash storage that cracks
       in seconds (NoLMHash), and NTLMv1 downgrade (LmCompatibilityLevel 5).
       Check the level on older releases and mixed domains; Windows 11 24H2 and
       Windows Server 2025 remove NTLMv1. ForceGuest 0 (Classic) keeps local
       users signing in over the network as themselves, and RestrictRemoteSAM
       limits remote SAM queries to Administrators. NULL session fallback 0 and
       NTLM minimum session security 537395200 (NTLMv2 session security plus
       128-bit encryption) close the last NTLM downgrades.
       LocalAccountTokenFilterPolicy 1 gives every local administrator a full
       token over C$ and ADMIN$ from the network, the pass-the-hash road;
       removing it keeps remote local admins filtered.
  NOTE: This is the registry form of the Watchman Security Options. A missing
        LocalAccountTokenFilterPolicy is the good result. MSV1_0 and the System
        key exist on every install, so Set-ItemProperty writes into them
        directly. On a domain controller, leave RestrictRemoteSAM undefined
        unless the brief asks for it: users and admin tools read Active
        Directory through remote SAM calls.

[A-05] User Rights Assignment
  AREA: Access control (CIS Control 6)
  GUI: secpol.msc, Local Policies, User Rights Assignment
      Access this computer from the network = Administrators, Authenticated Users (remove Everyone and Guest)
      Deny log on through Remote Desktop Services = Guest
      Deny access to this computer from the network = Guest
      Debug programs = empty, or Administrators only
      Act as part of the operating system = empty
      Back up files and directories, Restore files and directories, Take ownership of files or other objects = Administrators
      Manage auditing and security log = Administrators
      Change the system time = Administrators, LOCAL SERVICE
      Allow log on locally = Administrators on a member server, plus Users when the brief names people who sign in at this console
  CMD> secedit /export /cfg C:\Windows\Temp\ura.inf /areas USER_RIGHTS
  PS> Select-String -Path C:\Windows\Temp\ura.inf -Pattern 'SeDebugPrivilege|SeTcbPrivilege|SeNetworkLogonRight|SeBackupPrivilege|SeSecurityPrivilege'
  CMD> whoami /priv
  WHY: Debug programs means read LSASS means dump every password. Back up files
       and directories reads the SAM hive, Restore and Take ownership rewrite
       any file, and Manage auditing and security log can clear the Security log
       (event 1102). Rights are privileges that bypass ACLs, and attackers plant
       extra principals here.
  NOTE: The export lists holders as SIDs: *S-1-5-32-544 is Administrators,
        *S-1-5-32-545 Users, and *S-1-5-11 Authenticated Users; a SID that
        resolves to an unknown account belongs to a deleted or planted one. To
        set a right from the command line, put the line in a [Privilege Rights]
        template, such as SeDebugPrivilege = *S-1-5-32-544 (an empty value
        empties the right), and apply it as in A-01 with /areas USER_RIGHTS; it
        takes effect at the holder's next sign-in. LOCAL SERVICE, NETWORK
        SERVICE, and SERVICE keep the rights they hold by default: remove only
        user and group accounts. Rights changes write events 4704 and 4705.

  PS> Get-ChildItem -Path C:\Users,C:\ProgramData,C:\Windows\Temp -Recurse -Force -File -Include *.exe,*.dll,*.scr -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '^C:\\Users\\(All Users|Default User)\\' | Get-AuthenticodeSignature | Where-Object Status -ne 'Valid' | Select-Object Path,Status
  PS> Get-ChildItem 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree' -Recurse | Where-Object { -not $_.GetValue('SD') -and $_.GetValue('Id') } | Select-Object Name
  CMD> wevtutil sl Microsoft-Windows-TaskScheduler/Operational /e:true
  CMD> autorunsc.exe -accepteula -a * -c -nobanner   (Sysinternals, public)
  WHY: WMI event subscriptions and PowerShell profiles are the persistence spots
       checklists miss. Autoruns shows every auto-start location at once. A
       renamed hacking tool keeps its missing or broken signature, and a task
       whose SD value was deleted vanishes from Get-ScheduledTask and schtasks
       while it still runs.
  NOTE: Download Sysinternals tools only from Microsoft
        (learn.microsoft.com/sysinternals), and only where policy allows third-
        party tools on the machine. An unsigned program in Users, ProgramData,
        or Temp is a lead to check against the brief and the publisher, since
        plenty of legitimate tools ship unsigned. The wevtutil line turns on
        Task Scheduler history, which starts off.

[A-07] NTFS permissions
  AREA: Access control (CIS Control 6)
  CMD> icacls "C:\CompanyData" /save C:\Windows\Temp\acl.txt /t /c
  CMD> icacls "C:\CompanyData"
  CMD> icacls "C:\CompanyData" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "Users:(OI)(CI)RX" /t
  CMD> icacls "C:\CompanyData" /remove:g Everyone /t
  PS> Get-Acl "C:\CompanyData" | Format-List
  WHY: Everyone with Full control on a share or a Program Files folder means
       anyone can replace a binary that a service runs as SYSTEM. (OI) object
       inherit, (CI) container inherit, /t recurse, /inheritance:r stop
       inheriting.
  NOTE: Save first: icacls C:\ /restore C:\Windows\Temp\acl.txt puts the saved
        ACLs back (restore runs from the parent folder). *S-1-1-0 (Everyone) and
        *S-1-5-11 (Authenticated Users) work in place of the names in any
        display language, as in /remove:g *S-1-1-0. A folder made at the root of
        C: inherits Authenticated Users Modify, so read it before you trust it.

[A-08] Fine-grained auditing and PowerShell logging
  AREA: Audit logging (CIS Control 8)
  CMD> auditpol /set /subcategory:"Credential Validation" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Logon" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Account Lockout" /failure:enable
  CMD> auditpol /set /subcategory:"User Account Management" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Security Group Management" /success:enable
  CMD> auditpol /set /subcategory:"Process Creation" /success:enable
  CMD> reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f
  CMD> auditpol /set /subcategory:"Security System Extension" /success:enable
  CMD> auditpol /set /subcategory:"Audit Policy Change" /success:enable /failure:enable
  CMD> auditpol /set /subcategory:"Filtering Platform Connection" /success:disable /failure:disable
  CMD> reg add HKLM\SYSTEM\CurrentControlSet\Control\Lsa /v SCENoApplyLegacyAuditPolicy /t REG_DWORD /d 1 /f
  PS> if (-not (Test-Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging')) { New-Item -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging' -Force | Out-Null }
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging' -Name EnableScriptBlockLogging -Value 1 -Type DWord
  PS> Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational'; Id=4104} -MaxEvents 3 | Format-List TimeCreated,Message
  CMD> auditpol /get /category:*
  WHY: Subcategory settings take precedence over the nine legacy categories once
       Audit: Force audit policy subcategory settings is Enabled
       (SCENoApplyLegacyAuditPolicy 1). Credential Validation writes 4776 for
       every local-account password check, so a guessing run shows beside 4625.
       The command-line value fills the Process Command Line field of every
       4688. Security System Extension writes 4697, which names who installed a
       service. Script Block Logging (event 4104) records what every PowerShell
       script actually did, including the attacker's.
  NOTE: Run it after I-01: a category-wide command rewrites every subcategory in
        its category. Account Lockout has Failure events only (the lockout
        itself, 4740, comes from User Account Management), and Security Group
        Management has Success events only. Filtering Platform Connection floods
        the log after a category-wide run; turn it back on when the brief asks
        for connection auditing. auditpol names drop the Audit prefix that
        secpol shows, and each subcategory also takes a GUID that works in any
        display language, such as {0CCE923F-69AE-11D9-BED3-505054503030} for
        Credential Validation. On a domain, a GPO that defines advanced auditing
        re-applies its list at each refresh, so set the values there. PowerShell
        7 reads its own key,
        HKLM:\SOFTWARE\Policies\Microsoft\PowerShellCore\ScriptBlockLogging, and
        logs to PowerShellCore/Operational.

[A-09] Defender beyond on: exclusions, PUA, cloud, ASR
  AREA: Malware defenses (CIS Control 10)
  PS> Get-MpPreference | Select-Object ExclusionPath,ExclusionProcess,ExclusionExtension
  PS> Remove-MpPreference -ExclusionPath "C:\evil"
  CMD> reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Exclusions" /s
  PS> Get-MpPreference | Select-Object ThreatIDDefaultAction_Ids,ThreatIDDefaultAction_Actions
  PS> Remove-MpPreference -ThreatIDDefaultAction_Ids <id>
  PS> Set-MpPreference -PUAProtection Enabled -MAPSReporting Advanced -SubmitSamplesConsent SendAllSamples
  PS> Add-MpPreference -AttackSurfaceReductionRules_Ids 9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2 -AttackSurfaceReductionRules_Actions Enabled
  PS> Get-MpThreatDetection | Select-Object DomainUser,ProcessName,InitialDetectionTime
  WHY: Attackers rarely turn Defender off, too obvious. They exclude their
       folder. PUA protection catches junkware; the LSASS rule blocks the
       mimikatz class of attacks. A ThreatIDDefaultAction of 6 means Allow:
       Defender lets that one threat run, a hiding place beside exclusions.
  NOTE: An exclusion set by policy returns after Remove-MpPreference: set the
        policy to Not Configured in gpedit.msc (or delete the value under the
        policy key) first, then remove the local one.

[A-10] Active Directory attack surface: roastable and stale accounts
  AREA: Account management (CIS Control 5)
  PS> Search-ADAccount -PasswordNeverExpires | Select-Object Name
  PS> Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 | Select-Object Name,LastLogonDate
  PS> Get-ADUser -Filter {PasswordNotRequired -eq $true} | Select-Object Name
  PS> Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true} | Select-Object Name
  PS> Set-ADAccountControl -Identity alice -DoesNotRequirePreAuth $false -PasswordNotRequired $false
  PS> Get-ADUser -Filter {ServicePrincipalName -like "*"} -Properties ServicePrincipalName | Select-Object Name,ServicePrincipalName
  PS> Get-ADUser -Filter {AdminCount -eq 1} | Select-Object Name
  PS> Get-ADUser -Filter {TrustedForDelegation -eq $true} | Select-Object Name
  WHY: No Kerberos pre-auth means AS-REP roasting; an SPN on a user account
       means Kerberoasting; stale admins and never-expiring passwords are quiet
       persistence. Each flag is one cmdlet to find and one to fix.
  NOTE: Only service accounts should carry SPNs, and they need long passwords or
        group managed service accounts. After a service account's password
        changes, set the same password on the service: services.msc, the
        service, Log On tab. For SQL Server services, make that change in SQL
        Server Configuration Manager.

[A-11] SMB and LDAP signing
  AREA: Secure configuration (CIS Control 4)
  PS> Get-SmbServerConfiguration | Select-Object RequireSecuritySignature; Get-SmbClientConfiguration | Select-Object RequireSecuritySignature
  PS> Get-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\NTDS\Parameters' | Select-Object LDAPServerIntegrity,LdapEnforceChannelBinding
  PS> Set-SmbServerConfiguration -RequireSecuritySignature $true -EncryptData $true -Force
  PS> Set-SmbClientConfiguration -RequireSecuritySignature $true -Force
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\NTDS\Parameters' -Name LDAPServerIntegrity -Value 2 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\NTDS\Parameters' -Name LdapEnforceChannelBinding -Value 2 -Type DWord
  WHY: Required SMB signing kills NTLM relay to the file server; required LDAP
       signing and channel binding kill relay to the domain controller, which is
       how one weak host becomes domain admin.
  NOTE: Verify, do not assume: defaults differ by release and by how the domain
        was built (see Version notes). Before you require LDAP signing or
        channel binding on a DC, check that every client supports it.

[A-12] Verify, document, re-check
  CMD> gpresult /r
  CMD> net accounts
  PS> Get-MpComputerStatus | Select-Object RealTimeProtectionEnabled,AntivirusSignatureLastUpdated
  PS> Get-NetFirewallProfile | Select-Object Name,Enabled
  PS> Get-LocalGroupMember Administrators
  CMD> netstat -abno
  WHY: A change log of what, when, and why is how you reverse a change that
       broke something in thirty seconds instead of thirty minutes, and it is
       exactly how real incident response works.

[A-13] Version notes: Windows Server 2025
      This page targets Windows Server 2025 (Windows 11 shell: Settings, Windows Update). Several defaults changed: read the current value instead of assuming.
      SMB: 2025 requires signing on all outbound SMB connections; domain controllers require it inbound as before
      LDAP: new 2025 Active Directory deployments require LDAP signing by default; an upgraded domain may not, so read LDAPServerIntegrity (A-11)
      OpenSSH Server is installed by default; Server Manager, Local Server, Remote SSH Access turns sshd on or off. Unless the brief requires SSH, keep sshd stopped and Disabled
      Delegated managed service accounts (dMSA) are new: they migrate a legacy service account (A-10) to managed, randomized keys
      Removed: Windows PowerShell 2.0, NTLMv1, WordPad, SMTP Server, IIS 6 Management Console; WMIC is an optional feature on demand (use Get-CimInstance)
  WHY: Every other item on this page is written to hold across releases; what
       changed lives here, so a normal default is not mistaken for a finding and
       a changed default is not mistaken for a fix.

[A-14] Windows Installer: AlwaysInstallElevated off
  AREA: Access control (CIS Control 6)
  CMD> reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer
  CMD> reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer
  CMD> reg add HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /t REG_DWORD /d 0 /f
  CMD> reg add HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /t REG_DWORD /d 0 /f
  CMD> reg add HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v EnableUserControl /t REG_DWORD /d 0 /f
  GUI: gpedit.msc, Computer Configuration and User Configuration, Administrative Templates, Windows Components, Windows Installer: Always install with elevated privileges = Disabled
  WHY: When AlwaysInstallElevated is 1 in both HKLM and HKCU, Windows Installer
       runs any user's .msi as SYSTEM, a one-step privilege escalation that
       Microsoft strongly discourages. EnableUserControl 0 keeps install options
       in administrators' hands.
  NOTE: HKCU covers only the signed-in user: check each profile the brief keeps
        by signing in as that user, or read
        HKEY_USERS\<SID>\SOFTWARE\Policies\Microsoft\Windows\Installer. reg add
        creates a missing key and keeps the values already in it.

------------------------------ FIX OR BREAK? (practice cards) ------------------
  Brief: Authorized administrators: alice. Authorized users: bob, carol.
  Action: Remove bob from the Administrators group.
  Call: FIX. Bob is a standard user per the brief. Demoting that account is
             least privilege.

  Brief: Investigation 1: what is the MD5 hash of C:\Users\Public\secret.mp3?
  Action: Delete every media file on the machine first, then start the
          investigation questions.
  Call: CHECK FIRST. Answer the investigation question before you destroy the
                     evidence. Evidence first, fixes second.

  Brief: You log in as alice. Alice is an authorized administrator.
  Action: Change the password of every user including alice to a strong one.
  Call: CHECK FIRST. Changing the sign-in account's password is usually fine but
                     can lock you out if it is recorded wrong; the brief
                     decides. Record every password you set.

  Brief: Nothing in the brief mentions the backup agent installed under
         C:\Program Files\BackupAgent.
  Action: Delete C:\Program Files\BackupAgent because it looks like unknown
          software.
  Call: CHECK FIRST. Unrecognized is distinct from unauthorized. Check the
                     publisher, the service that runs it, and its scheduled
                     tasks, then ask the owner before removing a backup or
                     monitoring agent.

  Brief: This is the domain controller for corp.local. Authorized Domain Admins:
         alice, dsmith.
  Action: Remove svc_print from Domain Admins.
  Call: FIX. Unauthorized Domain Admin membership is the single most valuable
             fix on a domain controller.

  Brief: The DC runs DNS for the whole company.
  Action: Uninstall-WindowsFeature DNS to reduce attack surface.
  Call: BREAKS IT. Required role. Harden the zones (no transfers, secure
                   updates) instead.

  Brief: net accounts on the DC shows minimum password length 0.
  Action: Run net accounts /minpwlen:12 and move on to the next item.
  Call: CHECK FIRST. On a DC the Default Domain Policy overrides it. Verify with
                     Get-ADDefaultDomainPasswordPolicy and change the domain
                     policy.

  Brief: The Finance share is for the Finance group only.
  Action: Revoke-SmbShareAccess for Everyone on the Finance share and grant
          CORP\Finance Change.
  Call: FIX. Least privilege on a required share: keep it, scope it.

  Brief: IIS hosts the public company website; anonymous visitors must be able
         to read it.
  Action: Disable Anonymous Authentication on the Default Web Site.
  Call: BREAKS IT. That takes the public site offline. Keep anonymous read, turn
                   off directory browsing, and check the web root for webshells
                   instead.

  Brief: The DC is not a print server.
  Action: Stop and disable the Print Spooler service.
  Call: FIX. PrintNightmare class. Spooler off on any DC that does not print.

  Brief: Investigation 3: which account was added to Domain Admins on 3 October?
  Action: Clear the Security log to reduce noise before investigating.
  Call: BREAKS IT. That destroys the evidence (and logs event 1102 against you).
                   Filter for 4728 and 4756 instead.

  Brief: svc_sql runs the SQL service and must keep working.
  Action: Set-ADAccountControl -Identity svc_sql -DoesNotRequirePreAuth $false,
          give svc_sql a new 25-character random password, and update the SQL
          service's logon password to match.
  Call: FIX. Removes the AS-REP roast, and updating the service's stored logon
             password keeps SQL running.

  Brief: The intranet site on this server must stay reachable, and Get-
         WebBinding shows only an http binding on port 80.
  Action: Set Require SSL (sslFlags Ssl) on the site now.
  Call: BREAKS IT. With only an http binding, Require SSL refuses every request
                   and the site goes offline. Add an https binding with a
                   certificate first, then require SSL.

  Brief: The FTP site must let anonymous visitors download files; icacls on the
         FTP root shows Everyone:(OI)(CI)(M).
  Action: Save the ACL with icacls /save, then replace Everyone Modify with
          Everyone read and execute on the FTP root.
  Call: FIX. Anonymous downloads need read and execute only; Modify lets any
             visitor upload or replace files. The saved ACL makes the change
             reversible.

------------------------------ SPOT THE FINDING (output snippets) --------------
  Output of net accounts. Brief: minimum length 12, maximum age 60, history 24, lockout after 5. Tap the line that is the finding.
     Minimum password length:                 12
     Maximum password age (days):             60
  >> Lockout threshold:                       Never
     Length of password history maintained:   24
  WHY: Lockout threshold Never means unlimited password guesses. Set it to 5
       with net accounts /lockoutthreshold:5.

  Get-NetFirewallProfile output. Tap the finding.
     Domain    True
     Private   True
  >> Public    False
     DefaultInboundAction  Block
  WHY: The Public profile is off. A common misconfiguration leaves exactly one
       profile disabled.

  netstat -abno output. Tap the finding.
     TCP    0.0.0.0:135    LISTENING   [svchost.exe]
     TCP    0.0.0.0:445    LISTENING   System
  >> TCP    0.0.0.0:4444   LISTENING   [nc.exe]
     TCP    127.0.0.1:5040 LISTENING   [svchost.exe]
  WHY: A netcat listener on 4444 is a backdoor. Find its PID, its path, and
       whatever task or Run key starts it.

  Get-MpPreference output. Tap the finding.
     PUAProtection          : 1
  >> ExclusionPath          : {C:\Users\Public\Libraries}
     DisableRealtimeMonitoring : False
     MAPSReporting          : 2
  WHY: An exclusion on a Public folder is how malware hides from a running
       Defender. Remove it with Remove-MpPreference.

  Registry values under HKLM:\SYSTEM\CurrentControlSet\Control\Lsa. Tap the finding.
     RestrictAnonymous      : 1
     NoLMHash               : 1
  >> LmCompatibilityLevel   : 0
     LimitBlankPasswordUse  : 1
  WHY: LmCompatibilityLevel 0 sends LM and NTLMv1 responses, which crack in
       minutes. Set it to 5. Check the level on older releases and mixed
       domains; Windows 11 24H2 and Windows Server 2025 remove NTLMv1.

  Get-ADGroupMember "Domain Admins". Brief: authorized Domain Admins are alice, dsmith, and the built-in Administrator. Tap the finding.
     alice
     dsmith
  >> svc_print
     Administrator
  WHY: A service account in Domain Admins is the highest-value finding on a
       domain controller. Remove it and investigate what it runs.

  Get-ADUser output. Tap the finding.
     alice   Enabled True  PasswordNotRequired False
  >> bob     Enabled True  PasswordNotRequired True
     carol   Enabled True  PasswordNotRequired False
     krbtgt  Enabled False PasswordNotRequired False
  WHY: PasswordNotRequired True allows a blank password regardless of policy.
       Set-ADAccountControl -PasswordNotRequired $false, then reset the
       password.

  Get-WindowsFeature output filtered to Installed. The brief requires only AD DS and DNS. Tap the finding.
     AD-Domain-Services  Installed
     DNS                 Installed
  >> FS-SMB1             Installed
     RSAT-AD-Tools       Installed
  WHY: SMBv1 on a domain controller. Uninstall-WindowsFeature FS-SMB1, and keep
       -Remove for a final pass the brief allows.

  Get-DnsServerZone output. Tap the finding.
  >> corp.local   Primary  DynamicUpdate Secure   SecureSecondaries TransferAnyServer
     _msdcs.corp.local  Primary  DynamicUpdate Secure  SecureSecondaries NoTransfer
     0.in-addr.arpa  Primary  DynamicUpdate None  SecureSecondaries NoTransfer
     .  Forwarder
  WHY: TransferAnyServer lets anyone dump the zone. Set-DnsServerPrimaryZone
       -SecureSecondaries NoTransfer.

  Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true}. Tap the finding.
     Name: svc_sql
     Enabled: True
  >> DoesNotRequirePreAuth: True
     SamAccountName: svc_sql
  WHY: An account without pre-auth can be AS-REP roasted offline. Set-
       ADAccountControl -DoesNotRequirePreAuth $false.

  Get-CimInstance Win32_Service output: Name, StartName, PathName. Tap the finding.
     DNS        LocalSystem                 C:\Windows\system32\dns.exe
     EventLog   NT AUTHORITY\LocalService   C:\Windows\System32\svchost.exe -k LocalServiceNetworkRestricted -p
  >> HealthMon  LocalSystem                 C:\Users\Public\svc\health.exe
     W3SVC      LocalSystem                 C:\Windows\system32\svchost.exe -k iissvcs
  WHY: A SYSTEM service runs from a folder every user can write to, so the path
       marks it as planted, whatever its name. Record its path and hash, then
       stop, disable, and remove it.

  reg query of the Windows Update policy keys. The brief says this server updates straight from Microsoft. Tap the finding.
     NoAutoUpdate          REG_DWORD    0x0
     AUOptions             REG_DWORD    0x4
  >> UseWUServer           REG_DWORD    0x1
     ScheduledInstallDay   REG_DWORD    0x0
  WHY: UseWUServer 1 sends every update check to the WUServer address instead of
       Microsoft, while the brief says updates come straight from Microsoft, so
       updates stop while the service runs. Delete UseWUServer and WUServer from
       the policy keys, then check for updates.

  net share output. Tap the finding.
     C$        C:\            Default share
     IPC$                      Remote IPC
     ADMIN$    C:\Windows     Remote Admin
  >> tools$    C:\Users\Public\tools
  WHY: A $ hides a share from browsing and keeps it reachable. tools$ is an
       added share on a folder every user can write to: record it, then Remove-
       SmbShare -Name tools$ -Force when the brief leaves it out. The other
       three are the defaults.

  Get-MpPreference output. Tap the finding.
     PUAProtection                  : 1
     ThreatIDDefaultAction_Ids      : {2147519003}
  >> ThreatIDDefaultAction_Actions  : {6}
     DisableRealtimeMonitoring      : False
  WHY: Action 6 is Allow: Defender lets that threat ID run untouched. Remove-
       MpPreference -ThreatIDDefaultAction_Ids 2147519003, check the policy key
       for the same override, then scan.

  winrm get winrm/config/service, a few lines. Tap the finding.
     AllowRemoteAccess = true
  >> AllowUnencrypted = true
     Auth: Basic = false
     Auth: Kerberos = true
  WHY: AllowUnencrypted true lets WinRM take commands and passwords in the clear
       over HTTP. Set the WinRM Service policy Allow unencrypted traffic to
       Disabled (AllowUnencryptedTraffic 0) and read it back with winrm get
       winrm/config/service.

  UAC registry values. The brief requires a prompt on the secure desktop. Tap the finding.
     EnableLUA                  : 1
  >> ConsentPromptBehaviorAdmin : 0
     PromptOnSecureDesktop      : 1
     FilterAdministratorToken   : 1
  WHY: ConsentPromptBehaviorAdmin 0 lets admins elevate silently. Set 2 (Always
       notify) or 5, the default; with PromptOnSecureDesktop 1, both prompt on
       the secure desktop.

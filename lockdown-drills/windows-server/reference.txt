================================================================================
 02: WINDOWS SERVER HARDENING: SOLUTION WALKTHROUGH
     Windows Server 2025 (member server or domain controller)
 Training reference for virtual machines you own or are authorized to change.
 Three levels: L1 Doorman, L2 Watchman, L3 Hunter. Every item = COMMAND, WHY,
 NOTE, and the hardening AREA it belongs to; ALSO adds a second caution when
 an item needs one. No scripts by design: type it, read it, explain it. Item
 IDs match the Lockdown Drills trainer for this OS.
 Unofficial practice; not affiliated with or endorsed by Microsoft.

 COMMAND LEGEND: PS> runs in an elevated PowerShell and CMD> in an elevated
 Command Prompt. Type what follows the prefix, and replace each value in angle
 brackets, such as <name>, with a real one. GUI: lines walk through a window,
 and indented lines show values to set or read.

 HARDENING AREAS (CIS Critical Security Controls v8.1)
   Account management ........ CIS Control 5
   Access control ............ CIS Control 6
   Secure configuration ...... CIS Control 4 (software inventory: Control 2)
   Patching .................. CIS Control 7
   Malware defenses .......... CIS Control 10
   Audit logging ............. CIS Control 8
   Also tagged: Data protection (CIS Control 3); Investigation (forensics
   basics: answer questions and preserve evidence before you change things).
================================================================================

------------------------------ DOORMAN -----------------------------------------
 Lock the doors. Find the role first (standalone, member server, or domain
 controller), then users, admins, passwords, and policy where it takes effect:
 local or domain. Learn it first: Defense Ladder s2, "Desktop, member server, or
 domain controller."
 https://freeapp4that.store/defense-ladder/#sophomore/s2
--------------------------------------------------------------------------------
[B-00] Scenario brief and evidence first
  AREA: Investigation (forensics basics)
  GUI: open the scenario brief (the documented requirements for this machine) and write down authorized users, admins, required services, and anything forbidden
  PS> (Get-CimInstance Win32_ComputerSystem).DomainRole
      0-1 standalone or member workstation, 2-3 standalone or member server, 4-5 domain controller
  CMD> dsregcmd /status   (AzureAdJoined and DomainJoined show who else can push settings to this server)
  PS> Get-WindowsFeature AD-Domain-Services,DNS,DHCP,Web-Server,Web-Ftp-Server | Select-Object Name,Installed
  WHY: Read the brief: removing a user, role, or service it requires is an
       availability failure. Evidence first: answer the investigation
       questions before any change (Defense Ladder f1).
  NOTE: Unfamiliar is distinct from unauthorized. Before removing an agent,
        find what starts it, who owns it, and what it does, then ask the owner
        (Defense Ladder s1).
  ALSO: Member servers use local accounts and secpol; domain controllers use
        Active Directory and Group Policy.

[B-01] List users: local and domain
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Select-Object Name,Enabled,PasswordRequired,LastLogon
  PS> Get-ADUser -Filter * -Properties Enabled,PasswordNeverExpires,PasswordNotRequired,LastLogonDate | Select-Object Name,Enabled,PasswordNeverExpires,PasswordNotRequired,LastLogonDate
  CMD> net user /domain
  PS> Get-Command *LocalUser*   (member server; on a domain controller, Get-Command -Module ActiveDirectory)
  PS> Get-LocalUser | Get-Member   (lists every property you can select, such as Enabled)
  GUI: dsa.msc (Active Directory Users and Computers) on a DC; lusrmgr.msc on a member server
  WHY: Unauthorized accounts are backdoors. On a DC the local SAM is gone; every
       account is a domain account, so Get-ADUser is the list to compare with
       the brief.
  NOTE: PasswordNotRequired=True and PasswordNeverExpires=True are findings in
        their own right.

[B-02] Remove or disable an unauthorized user
  AREA: Account management (CIS Control 5)
  PS> Get-ScheduledTask | Where-Object { $_.Principal.UserId -like '*baduser' } | Select-Object TaskPath,TaskName
  PS> Get-CimInstance Win32_Service | Where-Object StartName -like '*baduser' | Select-Object Name,StartName,PathName
  PS> Disable-ADAccount -Identity baduser
  PS> Enable-ADAccount -Identity keola   (undo a disable once the owner confirms the account is needed)
  PS> Remove-ADUser -Identity baduser -Confirm:$false
  PS> Remove-LocalUser -Name "baduser"
  CMD> net user baduser /delete
  PS> Enable-LocalUser -Name keola   (member server: undo a disable once the brief confirms the account belongs)
  WHY: Disable first if the brief is unclear; delete when it is clear. A
       disabled account keeps its SID and group memberships for the
       investigation question.
  NOTE: First, answer every investigation question that names the account.
        Then handle each scheduled task or service running as that account;
        the first two commands find them.
  ALSO: Deletion leaves the profile under C:\Users: search it for evidence and
        prohibited files, then remove it.

[B-03] Audit the privileged groups
  AREA: Account management (CIS Control 5)
  PS> Get-ADGroupMember "Domain Admins"; Get-ADGroupMember "Enterprise Admins"; Get-ADGroupMember "Schema Admins"; Get-ADGroupMember "Administrators"
  PS> Get-ADGroupMember "Account Operators"; Get-ADGroupMember "Server Operators"; Get-ADGroupMember "Backup Operators"; Get-ADGroupMember "DnsAdmins"
  PS> Remove-ADGroupMember -Identity "Domain Admins" -Members baduser -Confirm:$false
  PS> Get-Help Get-LocalGroupMember -Examples   (worked examples; run Update-Help once, online, for the full text)
  PS> Get-LocalGroupMember -Group Administrators
  CMD> net localgroup Administrators baduser /delete
  PS> Remove-LocalGroupMember -Group Administrators -Member baduser   (member server)
  WHY: Domain Admins grants everything; the operator groups, Backup Operators,
       and DnsAdmins reach the same place quietly. Compare each group's members
       with the brief; on a member server, check local Administrators.

[B-04] Disable Guest; protect the built-in Administrator
  AREA: Account management (CIS Control 5)
  PS> Get-LocalUser | Where-Object { $_.SID -like '*-50[01]' } | Select-Object Name,Enabled,SID   (member server)
  PS> Get-ADUser -Filter * | Where-Object { $_.SID -like '*-50[01]' } | Select-Object Name,Enabled,SID   (domain controller)
  CMD> whoami /user
  CMD> net user Guest /active:no
  PS> Disable-LocalUser -Name Guest   (member server)
  PS> Disable-ADAccount -Identity Guest
  CMD> net user Administrator /active:no
  PS> Set-ADUser -Identity Administrator -PasswordNeverExpires $false
  PS> Get-LapsADPassword -Identity KAILUA-WS07 -AsPlainText   (Windows LAPS: each computer's own local Administrator password, rotated and readable only by granted groups)
  WHY: Well-known names invite brute force. Disable Guest; keep Administrator
       enabled only when the brief uses it, with a strong password. Match SID
       -500 (Administrator) and -501 (Guest) to catch renames.
  NOTE: Keep the account the brief tells you to log in with enabled; whoami
        /user shows your SID, and -500 marks the built-in Administrator.
  ALSO: Rename Administrator and Guest last, only when the brief or policy
        asks (Rename-LocalUser on a member server). The SID stays, so
        disabling and a strong password carry the protection.

[B-05] Strong passwords and forced change
  AREA: Account management (CIS Control 5)
  PS> Get-ADUser -Filter * -Properties PasswordLastSet,PasswordNeverExpires | Select-Object Name,Enabled,PasswordLastSet,PasswordNeverExpires
  PS> Set-ADAccountPassword -Identity alice -Reset -NewPassword (Read-Host -AsSecureString 'New password')
  PS> Set-ADUser -Identity alice -PasswordNeverExpires $false -PasswordNotRequired $false
  PS> Set-ADUser -Identity alice -ChangePasswordAtLogon $true
  PS> Get-ADUser -Identity alice -Properties PasswordNeverExpires,pwdLastSet | Select-Object Name,PasswordNeverExpires,pwdLastSet
  PS> Get-ADUser -Filter 'Enabled -eq $true' | Where-Object SamAccountName -ne $env:USERNAME | Set-ADUser -PasswordNeverExpires $false
  CMD> net user alice *
  CMD> net user alice /logonpasswordchg:yes
  PS> Set-LocalUser -Name alice -PasswordNeverExpires $false   (member server)
  WHY: Weak, shared, or blank passwords let attackers in. PasswordNotRequired
       allows blank ones despite policy; PasswordNeverExpires defeats aging.
       Clear both, force a change at next sign-in, and confirm pwdLastSet is
       0.
  NOTE: Apply B-06 and B-07 first so new passwords meet domain policy.
        Read-Host and net user * prompt, hiding passwords from command
        history; record them safely (on paper, in a lab).
  ALSO: The bulk line clears service accounts' PasswordNeverExpires, so their
        passwords expire. Exclude them by name, or handle them in A-10,
        updating each service's Log On tab at the same time.

[B-06] Password policy where it actually lives
  AREA: Account management (CIS Control 5)
  PS> Get-ADDefaultDomainPasswordPolicy
  PS> Set-ADDefaultDomainPasswordPolicy -Identity (Get-ADDomain).DNSRoot -MinPasswordLength 12 -ComplexityEnabled $true -PasswordHistoryCount 24 -MinPasswordAge 1.00:00:00 -MaxPasswordAge 60.00:00:00 -ReversibleEncryptionEnabled $false
  GUI: gpmc.msc, Default Domain Policy, Computer Configuration, Policies, Windows Settings, Security Settings, Account Policies, Password Policy
  CMD> net accounts /minpwlen:12 /maxpwage:60 /minpwage:1 /uniquepw:24   (member server)
  GUI: secpol.msc, Account Policies, Password Policy (member server)
  WHY: Default Domain Policy overrides net accounts and secpol.msc on DCs
       only. Passwords set while reversible encryption was on stay
       recoverable: reset them, and check accounts with Get-ADUser <name>
       -Properties AllowReversiblePasswordEncryption.
  NOTE: The brief sets the numbers; these are one sample. CIS Benchmark: 14 or
        more characters, history 24 or more, maximum age 1–365 days, minimum age
        1 day or more.

[B-07] Account lockout policy
  AREA: Account management (CIS Control 5)
  PS> Set-ADDefaultDomainPasswordPolicy -Identity (Get-ADDomain).DNSRoot -LockoutThreshold 5 -LockoutDuration 00:30:00 -LockoutObservationWindow 00:30:00
  CMD> net accounts /lockoutthreshold:5 /lockoutduration:30 /lockoutwindow:30   (member server)
  PS> Search-ADAccount -LockedOut | Select-Object Name
  PS> Unlock-ADAccount -Identity alice
  WHY: Turns an online brute force from thousands of guesses a minute into
       five per half hour. Search-ADAccount shows who is locked out right now,
       which is also an investigation clue.
  NOTE: The brief sets the numbers. The CIS Benchmark asks for a threshold of
        5 or fewer and above 0, and a duration and reset window of 15 minutes
        or more.
  ALSO: A member server's local built-in Administrator locks only with Allow
        Administrator account lockout Enabled (AllowAdministratorLockout = 1,
        Hunter A-01), only for network sign-ins like Remote Desktop. Console
        sign-in stays available.

[B-08] Firewall on for all profiles
  AREA: Secure configuration (CIS Control 4)
  PS> Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True
  PS> Get-NetFirewallProfile -PolicyStore ActiveStore | Select-Object Name,Enabled,DefaultInboundAction
  CMD> netsh advfirewall set allprofiles state on
  CMD> netsh advfirewall show allprofiles
  GUI: Settings, Privacy and security, Windows Security, Firewall and network
       protection.
  WHY: Default-deny inbound covers the service you have not found yet.
       Misconfigured machines often have exactly one profile off, usually
       Public.
  NOTE: DefaultInboundAction should be Block. ActiveStore shows values in
        force, Group Policy included; the plain view reads NotConfigured for
        values left at default (Block inbound). Watchman covers allow rules.

[B-09] Windows Update on a server
  AREA: Patching (CIS Control 7)
  CMD> sconfig   (option 5: Update setting = Automatic; option 6: Install Updates)
  GUI: Win+R, ms-settings:windowsupdate (Settings, Windows Update), Check for updates
  PS> Set-Service -Name wuauserv -StartupType Automatic; Start-Service wuauserv
  PS> Get-Service wuauserv,BITS,UsoSvc | Select-Object Name,Status,StartType
  PS> Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 5
  CMD> reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate /s
  CMD> reg delete HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate /v WUServer /f   (only when the brief rules out an update server; delete UseWUServer with it)
  CMD> reg delete HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate\AU /v UseWUServer /f   (the pair goes together: UseWUServer 1 keeps Windows looking for the deleted server)
  GUI: gpmc.msc (or gpedit.msc), Computer Configuration, Policies, Administrative Templates, Windows Components, Windows Update: Configure Automatic Updates = Enabled (4)
  PS> winget upgrade   (lists apps with newer versions; winget ships with Server 2025)
  CMD> shutdown /r /t 60 /c "Installing updates"   (warn signed-in users first: quser lists them)
  WHY: Patching closes known holes; automatic updates keep closing them. A
       reverting setting is GPO-owned: NoAutoUpdate 1 disables automatic
       updates; UseWUServer 1 sends checks to WUServer, which the brief must
       name.
  NOTE: Start updates early; recheck after each restart until Windows Update
        reports up to date. wuauserv ships as Manual (starts on demand);
        Disabled is the finding. Save work before any reboot.

[B-10] Microsoft Defender on Server
  AREA: Malware defenses (CIS Control 10)
  PS> Get-MpComputerStatus | Select-Object AMServiceEnabled,RealTimeProtectionEnabled,AntivirusSignatureLastUpdated
  PS> Get-MpComputerStatus | Select-Object AMRunningMode
  PS> Install-WindowsFeature -Name Windows-Defender
  PS> Set-MpPreference -DisableRealtimeMonitoring $false
  PS> Update-MpSignature
  PS> Start-MpScan -ScanType QuickScan
  PS> Start-MpScan -ScanType CustomScan -ScanPath C:\Users
  PS> Get-MpThreatDetection | Select-Object InitialDetectionTime,ProcessName,Resources
  GUI: Win+R, windowsdefender: (opens Windows Security), Virus and threat protection, Manage settings
  WHY: Windows Server ships with Defender, but someone can remove the feature
       or disable it by policy. Real-time protection and current signatures
       both matter, and Get-MpComputerStatus shows each.
  NOTE: Answer the investigation questions before any scan, because a scan can
        quarantine the file a question asks about. Record each detection's
        Resources path before removing the program that dropped it.
  ALSO: If Get-MpComputerStatus errors, the feature is missing: install it,
        restart when RestartNeeded says Yes, then configure. AMRunningMode
        Normal means active; Passive means another antivirus leads. The brief
        picks the product.

[B-11] Remove unapproved software
  AREA: Secure configuration: software (CIS Controls 2 and 4)
  PS> Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*, HKLM:\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall\*, Registry::HKEY_USERS\*\Software\Microsoft\Windows\CurrentVersion\Uninstall\* -ErrorAction SilentlyContinue | Select-Object DisplayName,DisplayVersion,Publisher,UninstallString | Sort-Object DisplayName
  GUI: Settings, Apps, Installed apps (or appwiz.cpl)
  WHY: Hacking tools, games, torrent clients, and remote-access tools are
       acceptable-use violations and attack surface.
  NOTE: Software the brief requires stays. Portable tools appear only in a
        file search (B-12, A-06). After removing a remote-access tool, check
        for its leftover service (I-04) and firewall rule (I-12).
  ALSO: The registry listing is instant; Win32_Product is slow and can trigger
        repairs. HKEY_USERS adds signed-in users' own apps. Remove capture
        tools' separate Npcap install when the brief omits packet capture.

[B-12] Find unapproved media and loose executables
  AREA: Data protection (CIS Control 3)
  PS> Get-ChildItem -Path C:\Users,C:\inetpub,C:\Shares -Recurse -Force -File -Include *.mp3,*.mp4,*.wav,*.avi,*.mkv,*.flac,*.mov,*.m4a,*.mpg,*.mpeg,*.ogg,*.flv,*.wma,*.aac -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\|^C:\\Users\\(All Users|Default User)\\' | Select-Object FullName
  CMD> dir /s /a /b C:\Users\*.mp3 C:\Users\*.mp4
  CMD> del /s /a C:\Users\*.mp3 C:\Users\*.mp4   (after dir /s /a /b lists the same files and the brief bans them; del also reaches AppData, where apps keep their own sounds, so check that list for AppData paths first)
  CMD> rd /s /q "C:\Users\<user>\Music\<folder>"   (a folder of banned files, after dir lists it: rd removes the folder and everything in it)
  PS> Get-ChildItem -Path C:\Users -Recurse -Force -File -Include *.mp3,*.mp4 -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\' | Remove-Item -Force   (after the list above is reviewed and any file a question names is hashed)
  PS> Get-ChildItem -Path C:\Users,C:\inetpub -Recurse -Force -File -Include *.exe,*.bat,*.cmd,*.ps1,*.vbs,*.hta,*.aspx,*.py,*.jar,*.zip,*.7z,*.rar -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\Local\\(Microsoft|Packages)\\|^C:\\Users\\(All Users|Default User)\\' | Select-Object FullName,LastWriteTime
  PS> Get-Item 'C:\Users\<user>\Downloads\<file>' -Stream * | Select-Object Stream,Length
  PS> Get-Content 'C:\Users\<user>\Downloads\<file>' -Stream Zone.Identifier   (ZoneId=3 marks a file downloaded from the internet)
  PS> Unblock-File -Path 'C:\Users\<user>\Downloads\<file>'   (only for an expected file from a trusted source: it removes the downloaded-from-the-internet mark)
  CMD> tar -tf "C:\Users\<user>\Downloads\<archive>.zip"
  WHY: Media in user profiles and web roots is the usual acceptable-use
       violation; a stray .aspx or .ps1 under inetpub is a webshell. Confirm
       each file against the brief before deleting.
  NOTE: First answer every investigation question naming a file and record its
        hash (B-14); then delete it and log the path. tar -tf lists a .zip's
        contents before you delete it.
  ALSO: Search C:\ too, beyond C:\Users. -Force shows hidden files; the
        filters skip AppData caches and the All Users and Default User links.
        Keep Python and other runtimes the brief needs.

[B-13] Stop obviously unsafe services
  AREA: Secure configuration (CIS Control 4)
  PS> Get-Service -Name ftpsvc,TermService,RemoteRegistry,SNMP -ErrorAction SilentlyContinue | Select-Object Name,Status,StartType
  PS> Stop-Service -Name RemoteRegistry; Set-Service -Name RemoteRegistry -StartupType Disabled
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 1
  PS> Get-NetFirewallRule -Group '@FirewallAPI.dll,-28752' -ErrorAction SilentlyContinue | Disable-NetFirewallRule
  CMD> reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services" /v fDenyTSConnections
  PS> Get-WindowsFeature Remote-Assistance
  GUI: services.msc, Startup type Disabled; Settings, System, Remote Desktop
  PS> Stop-Service -Name Spooler; Set-Service -Name Spooler -StartupType Disabled   (unless this is the print server)
  PS> Get-NetTCPConnection -State Listen -LocalPort 21,3389 -ErrorAction SilentlyContinue
  WHY: Telnet and FTP leak cleartext credentials, Remote Registry allows remote
       registry edits, RDP draws brute force, and a domain controller's Print
       Spooler is PrintNightmare. Confirm: the port check returns empty.
  NOTE: If the brief requires RDP, FTP, or SSH, harden it instead of killing it
        (I-11). Remote management tools use Remote Registry on a server: disable
        it when the brief names local administration only, and record the
        change. Turning Remote Desktop off takes the setting plus its firewall
        group (the @FirewallAPI name works in any display language).
        fDenyTSConnections 0 under the Terminal Services policy key forces
        Remote Desktop back on, so an error that the value is missing is the
        good result. When the brief leaves Remote Assistance out, run
        Uninstall-WindowsFeature Remote-Assistance. The last line returns empty once FTP
        and Remote Desktop stop listening.

[B-14] Hash a file for an investigation question
  AREA: Investigation (forensics basics)
  PS> Get-FileHash -LiteralPath 'C:\Users\<user>\Desktop\<file>' -Algorithm SHA256 | Format-List
  CMD> certutil -hashfile "C:\Users\<user>\Desktop\<file>" SHA256
  PS> Format-Hex -Path 'C:\Users\<user>\Desktop\<file>' | Select-Object -First 1   (the first bytes name the real type: 4D 5A is an .exe, 25 50 44 46 is a PDF; PowerShell 7 adds -Count 8)
  PS> Get-MpThreatDetection | Select-Object InitialDetectionTime,Resources
  WHY: Answer with the named algorithm's exact hex string, which repeats on
       every run. Hash before any Defender scan, cleanup, or move: changed or
       quarantined, the file answers differently or vanishes.
  NOTE: Check each hash's length: MD5 32 hex characters, SHA1 40, SHA256 64.
        certutil defaults to SHA1, so name the algorithm. -LiteralPath reads
        names with [ ] that -Path skips.
  ALSO: Quotes keep paths with spaces whole. If opening the file reports a
        virus, Defender already quarantined it: Get-MpThreatDetection and
        Windows Security, Protection history show the path and time to record.

[B-15] Create the users and groups the brief lists
  AREA: Account management (CIS Control 5)
  PS> New-ADUser -Name 'kekoa' -SamAccountName 'kekoa' -AccountPassword (Read-Host -AsSecureString 'Password') -Enabled $true
  PS> New-ADGroup -Name 'Accounting' -GroupScope Global
  PS> Add-ADGroupMember -Identity 'Accounting' -Members kekoa
  PS> Get-ADGroupMember -Identity 'Accounting'
  CMD> net user kekoa * /add   (member server)
  PS> New-LocalUser -Name 'kekoa' -Password (Read-Host -AsSecureString 'Password')   (member server)
  PS> New-LocalGroup -Name Accounting   (member server)
  CMD> net localgroup Accounting /add   (member server)
  CMD> net localgroup Accounting kekoa /add   (member server)
  PS> Add-LocalGroupMember -Group Accounting -Member kekoa   (member server)
  WHY: A listed user or group missing from the machine locks someone out of
       sign-in and the job's files. Create exactly that set; the brief is the
       source of truth.
  NOTE: Read-Host and net user * prompt for the password, keeping it out of
        command history. Security events 4720 (account created) and 4728 (added
        to a global group) record each step.

[B-16] Find files that store passwords
  AREA: Data protection (CIS Control 3)
  PS> Get-ChildItem -Path C:\Users,C:\inetpub,C:\Shares -Recurse -Force -File -Include *.txt,*.csv,*.ini,*.xml,*.log,*.ps1,*.bat -ErrorAction SilentlyContinue | Where-Object FullName -notmatch '\\AppData\\Local\\|^C:\\Users\\(All Users|Default User)\\' | Select-String -Pattern 'passw(or)?d|pwd|credential' -List | Select-Object Path,LineNumber,Line
  CMD> findstr /s /i /m /c:"password" C:\Users\*.txt C:\Users\*.csv C:\Users\*.ini
  PS> Get-ChildItem -Path C:\Users\*\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt -Force -ErrorAction SilentlyContinue | Select-String -Pattern 'net user|ConvertTo-SecureString|passw' | Select-Object Path,Line
  PS> Get-ChildItem -Path C:\Windows\Panther\Unattend.xml,C:\Windows\Panther\Unattend\Unattend.xml,C:\Windows\System32\Sysprep\unattend.xml -Force -ErrorAction SilentlyContinue | Select-String -Pattern '<Password>|AdministratorPassword' | Select-Object Path,LineNumber
  CMD> cmdkey /list
  WHY: Passwords in notes, scripts, PowerShell history, or Windows Setup
       answer files expose accounts. Hidden answer-file passwords are only
       encoded: treat them as plaintext. Content search finds them under any
       name.
  NOTE: First answer any investigation question that names the file and record
        its hash (B-14). Then remove or move it where the brief says, and log
        the path.
  ALSO: Review each hit: license and app files match too. cmdkey /list shows
        only the signed-in user's saved passwords, like TERMSRV/<host> for
        Remote Desktop; cmdkey /delete:<target> removes one the brief omits.

------------------------------ WATCHMAN ----------------------------------------
 Check the windows. Roles and features, audit and policy through Group Policy,
 services, shares, tasks, ports, logs, and the required roles (IIS, FTP, DNS,
 and DHCP) hardened rather than removed. Learn it first: Defense Ladder j1,
 "Windows Server and Active Directory," and Defense Ladder j2, "Group Policy."
 https://freeapp4that.store/defense-ladder/#junior/j1
 https://freeapp4that.store/defense-ladder/#junior/j2

[I-01] Audit policy: turn the lights on
  AREA: Audit logging (CIS Control 8)
  CMD> wevtutil sl Security /ms:201326592
  CMD> wevtutil gl Security   (maxSize shows the new limit)
  CMD> auditpol /backup /file:C:\Windows\Temp\audit-before.csv
  CMD> auditpol /set /category:* /success:enable /failure:enable
  CMD> auditpol /get /category:*
  GUI: gpmc.msc, Default Domain Controllers Policy, Computer Configuration, Policies, Windows Settings, Security Settings, Advanced Audit Policy Configuration
  WHY: Without auditing, Event Viewer has nothing to tell you or an
       investigator. Logon, account management, and policy change are the key
       ones.
  NOTE: On a DC the Default Domain Controllers Policy overrides local auditpol:
        set it there or it reverts at the next gpupdate. Pick one route,
        auditpol here or Advanced Audit Policy Configuration in Group Policy,
        and leave secpol's basic Audit Policy node unset; Microsoft warns that
        mixing the two gives unexpected results, so trust auditpol /get.
        wevtutil raises the Security log to 192 MB first so the extra events
        keep older evidence; auditpol /restore
        /file:C:\Windows\Temp\audit-before.csv undoes the change. Fine-grained
        subcategories, and trimming the noisiest ones, are A-08.

[I-02] Security Options in secpol.msc
  AREA: Secure configuration (CIS Control 4)
  GUI: secpol.msc, Local Policies, Security Options
      Accounts: Limit local account use of blank passwords to console logon only = Enabled
      Devices: Prevent users from installing printer drivers = Enabled
      Interactive logon: Don't display last signed-in = Enabled (older label: Do not display last user name)
      Interactive logon: Machine inactivity limit = 900 seconds or fewer
      Interactive logon: Do not require CTRL+ALT+DEL = Disabled
      Network access: Do not allow anonymous enumeration of SAM accounts and shares = Enabled
      Network security: LAN Manager authentication level = Send NTLMv2 response only. Refuse LM & NTLM
      Microsoft network client and server: Digitally sign communications (always) = Enabled
      Shutdown: Allow system to be shut down without having to log on = Disabled
      User Account Control: Run all administrators in Admin Approval Mode = Enabled
      Domain controller: LDAP server signing requirements = Require signing
      Domain member: Digitally encrypt or sign secure channel data (always) = Enabled
  WHY: Classic CIS and STIG level-one settings. Each blocks a named attack:
       blank-password remote logon, username harvesting, LM and NTLMv1
       cracking or relay, SMB relay, shutdown before sign-in, and UAC bypass.
  NOTE: The inactivity limit locks every idle session. A VM sends the required
        CTRL+ALT+DEL from its window menu or Ctrl+Alt+End (Hyper-V, Remote
        Desktop). Command line: Hunter A-02 (registry) or A-01 (secedit).
  ALSO: Releases older than Windows 11 24H2 and Windows Server 2025 still
        accept NTLMv1: check the LAN Manager authentication level there and in
        mixed domains.

[I-03] UAC to Always notify
  AREA: Secure configuration (CIS Control 4)
  GUI: Win+R, UserAccountControlSettings: move the slider to the top, Always notify
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name EnableLUA -Value 1 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System' -Name ConsentPromptBehaviorAdmin -Value 2 -Type DWord

[A-02] LSA and anonymous-access registry hardening

  PS> Set-ItemProperty -Path $lsa -Name RestrictAnonymous -Value 1 -Type DWord

  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name NTLMMinClientSec -Value 537395200 -Type DWord
  PS> Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0' -Name NTLMMinServerSec -Value 537395200 -Type DWord

        Directory through remote SAM calls.

------------------------------ FIX OR BREAK? (practice cards) ------------------
  Brief: Authorized administrators: alice. Authorized users: bob, carol.
  Action: Remove bob from the Administrators group.
  Call: FIX. Bob is a standard user per the brief. Demoting that account is
             least privilege.

  Brief: Investigation 1: what is the MD5 hash of C:\Users\Public\secret.mp3?
  Action: Delete every media file on the machine first, then start the
          investigation questions.
  Call: CHECK FIRST. Answer the investigation question before you destroy the
                     evidence. Evidence first, fixes second.

  Brief: You log in as alice. Alice is an authorized administrator.
  Action: Change the password of every user including alice to a strong one.
  Call: CHECK FIRST. Changing the sign-in account's password is usually fine but
                     can lock you out if it is recorded wrong; the brief
                     decides. Record every password you set.

  Brief: Nothing in the brief mentions the backup agent installed under
         C:\Program Files\BackupAgent.
  Action: Delete C:\Program Files\BackupAgent because it looks like unknown
          software.
  Call: CHECK FIRST. Unrecognized is distinct from unauthorized. Check the
                     publisher, the service that runs it, and its scheduled
                     tasks, then ask the owner before removing a backup or
                     monitoring agent.

  Brief: This is the domain controller for corp.local. Authorized Domain Admins:
         alice, dsmith.
  Action: Remove svc_print from Domain Admins.
  Call: FIX. Unauthorized Domain Admin membership is the single most valuable
             fix on a domain controller.

  Brief: The DC runs DNS for the whole company.
  Action: Uninstall-WindowsFeature DNS to reduce attack surface.
  Call: BREAKS IT. Required role. Harden the zones (no transfers, secure
                   updates) instead.

  Brief: net accounts on the DC shows minimum password length 0.
  Action: Run net accounts /minpwlen:12 and move on to the next item.
  Call: CHECK FIRST. On a DC the Default Domain Policy overrides it. Verify with
                     Get-ADDefaultDomainPasswordPolicy and change the domain
                     policy.

  Brief: The Finance share is for the Finance group only.
  Action: Revoke-SmbShareAccess for Everyone on the Finance share and grant
          CORP\Finance Change.
  Call: FIX. Least privilege on a required share: keep it, scope it.

  Brief: IIS hosts the public company website; anonymous visitors must be able
         to read it.
  Action: Disable Anonymous Authentication on the Default Web Site.
  Call: BREAKS IT. That takes the public site offline. Keep anonymous read, turn
                   off directory browsing, and check the web root for webshells
                   instead.

  Brief: The DC is not a print server.
  Action: Stop and disable the Print Spooler service.
  Call: FIX. PrintNightmare class. Spooler off on any DC that does not print.

  Brief: Investigation 3: which account was added to Domain Admins on 3 October?
  Action: Clear the Security log to reduce noise before investigating.
  Call: BREAKS IT. That destroys the evidence (and logs event 1102 against you).
                   Filter for 4728 and 4756 instead.

  Brief: svc_sql runs the SQL service and must keep working.
  Action: Set-ADAccountControl -Identity svc_sql -DoesNotRequirePreAuth $false,
          give svc_sql a new 25-character random password, and update the SQL
          service's logon password to match.
  Call: FIX. Removes the AS-REP roast, and updating the service's stored logon
             password keeps SQL running.

  Brief: The intranet site on this server must stay reachable, and
         Get-WebBinding shows only an http binding on port 80.
  Action: Set Require SSL (sslFlags Ssl) on the site now.
  Call: BREAKS IT. With only an http binding, Require SSL refuses every request
                   and the site goes offline. Add an https binding with a
                   certificate first, then require SSL.

  Brief: The FTP site must let anonymous visitors download files; icacls on the
         FTP root shows Everyone:(OI)(CI)(M).
  Action: Save the ACL with icacls /save, then replace Everyone Modify with
          Everyone read and execute on the FTP root.
  Call: FIX. Anonymous downloads need read and execute only; Modify lets any
             visitor upload or replace files. The saved ACL makes the change
             reversible.

  Brief: Staff map shares on this file server, and the brief requires the
         firewall on every profile. A staff PC's ping to the server times out
         while its mapped drive works.
  Action: Turn off Windows Firewall on this server so ping answers.
  Call: BREAKS IT. The brief requires the firewall, and a silent ping proves
                   little: Windows Firewall blocks inbound echo requests unless
                   a rule allows them. Test-NetConnection <server> -Port 445
                   from the PC tests the share itself.

  Brief: The brief requires BitLocker on this server's C: drive.
         Get-BitLockerVolume shows C: FullyDecrypted with an empty KeyProtector
         list.
  Action: Run Add-BitLockerKeyProtector -MountPoint C:
          -RecoveryPasswordProtector, save the recovery password off the server,
          then run Enable-BitLocker -MountPoint C: -TpmProtector.
  Call: FIX. That is the safe order: the recovery password exists, and sits away
             from the server, before encryption starts, so a TPM change after a
             firmware update still leaves a way back in.

       password.

  Get-WindowsFeature output filtered to Installed. The brief requires only AD DS and DNS. Tap the finding.
     AD-Domain-Services  Installed
     DNS                 Installed
  >> FS-SMB1             Installed
     RSAT-AD-Tools       Installed
  WHY: SMBv1 on a domain controller. Uninstall-WindowsFeature FS-SMB1, and keep
       -Remove for a final pass the brief allows.

  Get-DnsServerZone output. Tap the finding.
  >> corp.local   Primary  DynamicUpdate Secure   SecureSecondaries TransferAnyServer
     _msdcs.corp.local  Primary  DynamicUpdate Secure  SecureSecondaries NoTransfer
     0.in-addr.arpa  Primary  DynamicUpdate None  SecureSecondaries NoTransfer
     .  Forwarder
  WHY: TransferAnyServer lets anyone dump the zone. Set-DnsServerPrimaryZone
       -SecureSecondaries NoTransfer.

  Get-ADUser -Filter {DoesNotRequirePreAuth -eq $true}. Tap the finding.
     Name: svc_sql
     Enabled: True
  >> DoesNotRequirePreAuth: True
     SamAccountName: svc_sql
  WHY: An account without pre-auth can be AS-REP roasted offline.
       Set-ADAccountControl -DoesNotRequirePreAuth $false.

  Get-CimInstance Win32_Service output: Name, StartName, PathName. Tap the finding.
     DNS        LocalSystem                 C:\Windows\system32\dns.exe
     EventLog   NT AUTHORITY\LocalService   C:\Windows\System32\svchost.exe -k LocalServiceNetworkRestricted -p
  >> HealthMon  LocalSystem                 C:\Users\Public\svc\health.exe
     W3SVC      LocalSystem                 C:\Windows\system32\svchost.exe -k iissvcs
  WHY: A SYSTEM service runs from a folder every user can write to, so the path
       marks it as planted, whatever its name. Record its path and hash, then
       stop, disable, and remove it.

  reg query of the Windows Update policy keys. The brief says this server updates straight from Microsoft. Tap the finding.
     NoAutoUpdate          REG_DWORD    0x0
     AUOptions             REG_DWORD    0x4
  >> UseWUServer           REG_DWORD    0x1
     ScheduledInstallDay   REG_DWORD    0x0
  WHY: UseWUServer 1 sends every update check to the WUServer address instead of
       Microsoft, while the brief says updates come straight from Microsoft, so
       updates stop while the service runs. Delete UseWUServer and WUServer from
       the policy keys, then check for updates.

  net share output. Tap the finding.
     C$        C:\            Default share
     IPC$                      Remote IPC
     ADMIN$    C:\Windows     Remote Admin
  >> tools$    C:\Users\Public\tools
  WHY: A $ hides a share from browsing and keeps it reachable. tools$ is an
       added share on a folder every user can write to: record it, then
       Remove-SmbShare -Name tools$ -Force when the brief leaves it out. The other
       three are the defaults.

  Get-MpPreference output. Tap the finding.
     PUAProtection                  : 1
     ThreatIDDefaultAction_Ids      : {2147519003}
  >> ThreatIDDefaultAction_Actions  : {6}
     DisableRealtimeMonitoring      : False
  WHY: Action 6 is Allow: Defender lets that threat ID run untouched.
       Remove-MpPreference -ThreatIDDefaultAction_Ids 2147519003, check the policy key
       for the same override, then scan.

  winrm get winrm/config/service, a few lines. Tap the finding.
     AllowRemoteAccess = true
  >> AllowUnencrypted = true
     Auth: Basic = false
     Auth: Kerberos = true
  WHY: AllowUnencrypted true lets WinRM take commands and passwords in the clear
       over HTTP. Set the WinRM Service policy Allow unencrypted traffic to
       Disabled (AllowUnencryptedTraffic 0) and read it back with winrm get
       winrm/config/service.

  UAC registry values. The brief requires a prompt on the secure desktop. Tap the finding.
     EnableLUA                  : 1
  >> ConsentPromptBehaviorAdmin : 0
     PromptOnSecureDesktop      : 1
     FilterAdministratorToken   : 1
  WHY: ConsentPromptBehaviorAdmin 0 lets admins elevate silently. Set 2 (Always
       notify) or 5, the default; with PromptOnSecureDesktop 1, both prompt on
       the secure desktop.

  Get-BitLockerVolume -MountPoint C: | Format-List, a few lines. Tap the finding.
     VolumeStatus         : FullyEncrypted
     EncryptionPercentage : 100
     KeyProtector         : {RecoveryPassword, Tpm}
  >> ProtectionStatus     : Off
  WHY: ProtectionStatus Off on a FullyEncrypted drive means protection is
       suspended: the key sits unprotected on the disk. Run Resume-BitLocker
       -MountPoint C:, then read Get-BitLockerVolume again.

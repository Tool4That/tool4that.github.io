LOCKDOWN RANGE: CISCO IOS - SOLUTION WALKTHROUGH
================================================
File: cisco-range.html (single page, works offline; progress stays in the
browser). Companion to the Windows Range and Linux Range labs.
A general networking-security practice lab for learners, instructors and
study groups. Every name, address and organization in the scenarios is
fictional. Unofficial practice; not affiliated with or endorsed by Cisco.
The look and feel is inspired by Cisco Packet Tracer, a free network
simulator.

1. WHAT THE LAB SIMULATES (AND WHAT IT DOES NOT)
------------------------------------------------
A Packet Tracer-style practice topology with real-feeling Cisco IOS consoles
and PC command prompts, plus a live Progress Check that re-runs every check
as you work.

Simulated faithfully:
- IOS modes and prompts: Router> Router# (config)# (config-if)#
  (config-if-range)# (config-subif)# (config-line)# (config-vlan)#
  (config-std-nacl)# (config-router)#; unique-prefix abbreviations (conf t,
  int g0/0, sh run, wr); ? context help; Tab completion; Up/Down history;
  Ctrl+Z; Ctrl+C.
- The exact error strings: % Invalid input detected at '^' marker. (caret
  under the bad word), % Ambiguous command:  "...", % Incomplete command.,
  % Bad secrets, % Bad passwords, % Login invalid, % No password set,
  % Please define a hostname other than Router., % Please define a
  domain-name first., Command rejected: ... is a dynamic port., % Password
  too short ..., % Login disabled on line N, until 'password' is set,
  % Only classful networks will be redistributed, % Configuring IP routing
  on a LAN subinterface is only allowed if that subinterface is already
  configured as part of an IEEE 802.10, IEEE 802.1Q, or ISL vLAN., etc.
- show running-config rendered from device state in true IOS order with
  enable secret 5 $1$mERr$..., username ... secret 5 ..., password 7 ...
  (real type-7 encoding) once service password-encryption is on, banner
  motd ^C...^C, grouped line vty blocks, end.
- copy running-config startup-config / write, show startup-config, and
  reload (asks to save, then boots from startup-config: unsaved work is
  gone, and the Progress Check drops with it).
- A real layer-2/layer-3 model: access and trunk ports (802.1Q, native VLAN,
  allowed list, DTP dynamic auto/desirable), router-on-a-stick
  subinterfaces (encapsulation dot1Q N [native]), SVIs that come up once
  their VLAN exists and has an active port, ip default-gateway on switches,
  standard ACLs on VTY lines (access-class), and login block-for quiet mode.
  ping / traceroute / tracert / ssh / telnet are evaluated against that
  model, with IOS and Windows style output (!!!!! / ..... / U.U.U, Request
  timed out., Destination host unreachable., TTL that drops per router hop).
- Routing tables built like IOS 15: connected (C) and local (L) routes,
  static routes (S, with an optional distance for floating backups) that
  install while their next hop sits on an up, connected subnet, and OSPF.
  show ip route groups entries under their classful network ("is subnetted"
  or "is variably subnetted"), in numeric order; the lowest administrative
  distance wins (connected 0, static 1, OSPF 110).
- OSPF in one area on Ethernet links: router ospf N, network A W area N,
  passive-interface, router-id, and redistribute static [subnets].
  Neighbours reach FULL (DR/BDR; the first router up on a segment stays DR)
  when both ends share the subnet, mask, and area; routers learn O routes
  and O E2 externals ([110/20]), and a local static route beats the
  neighbour's O E2 copy until the local uplink fails.
  show ip ospf neighbor / database / interface brief and show ip protocols
  read that state; %OSPF-5-ADJCHG messages log adjacency changes.
- Switch VLANs live in flash:vlan.dat: they survive a reload without
  copy running-config startup-config, and show flash: lists vlan.dat.
- CDP reports a native VLAN mismatch between trunk ends
  (%CDP-4-NATIVE_VLAN_MISMATCH) on the switch console, and the topology
  draws that link in amber.
- Numbered ACL editing like real IOS: "no access-list 10 permit host X"
  deletes the WHOLE list 10; remove one entry with "ip access-list standard
  10" then "no <sequence number>" (show access-lists prints the numbers).
- SSH from a PC or device succeeds only when the target is fully ready
  (RSA key, login local, a matching username/secret, transport input ssh,
  ACL permits the source) and then drops you into that device's vty
  session. Telnet works only when the line allows it and has a password
  (and leaves the SSH-only check failing until it is closed).
- Port security with sticky learning, BPDU guard / portfast [trunk], DHCP
  snooping configuration, CDP neighbours, MAC address table, logging buffer
  with syslog-style %LINK / %LINEPROTO / %SYS-5-CONFIG_I / %SSH-5-ENABLED
  lines, show version / show clock / show ip ssh / show port-security /
  show interfaces X switchport | trunk ...
- Two router models: the 1941 (Levels 1-3) and the 2911 (Level 4, three
  Gigabit ports). A factory router has VTY lines 0-4; line vty 0 15 creates
  lines 5-15. Switches and routers list 16 VTY lines as line vty 0 4 and
  line vty 5 15 in show running-config.

Deliberately NOT simulated (the console tells you with a [Range] note):
- Output paging (--More--): everything scrolls; use the browser scrollback.
- erase startup-config / write erase, copy startup-config running-config
  (the real merge), the setup dialog itself (a factory device offers it:
  answer no), debug output, extended ping options, SNMP, AAA (aaa
  new-model), RIP, EIGRP, and BGP (OSPF is simulated), redistribute
  connected, IPv6, NAT, extended or interface ACLs
  (ip access-group), storm control, and DHCP server/client.
- Real DNS behaviour on an unknown first word in EXEC mode: the real router
  prints Translating "shw"... and tries to telnet; the lab always gives
  the ^ marker error so the message you learn is the one that matters.
- Port-security violations never actually happen (every PC keeps its MAC).
- NTP and syslog servers sit outside the topology, so NTP stays
  unsynchronized and syslog messages go undelivered; the checks read the
  configuration alone.

How progress is measured:
- Checks: each scenario has 22-27 checks worth 100 points in total. Each
  check belongs to a hardening area (the same areas the Windows and Linux
  labs use):
    Account management   - enable secret, local accounts, password
                           encryption and length
    Access control       - console/VTY login, SSH only, RSA keys,
                           timeouts, login block-for, VTY ACLs, port
                           security
    Secure configuration - hostname, banner, unneeded services, unused
                           ports, VLANs, trunks, PortFast and BPDU guard,
                           DHCP snooping, CDP, routing, saved config
    Audit logging        - syslog host, timestamps, NTP
  Patching and Malware defenses have no checks in this lab. Two groups sit
  outside the six areas: Troubleshooting (restoring a broken path) and
  Investigation (questions you answer by reading the devices).
  The six areas and their CIS Controls: Defense Ladder s1
  (https://freeapp4that.store/defense-ladder/#sophomore/s1).
- Grade levels and lessons: Level 1 Recruit is Sophomore, Level 2 Operator
  is Junior, and Levels 3 Captain and 4 Two sites are Senior. The level
  pills show the grade, and each Debrief links to the Defense Ladder
  lessons behind that level (listed under each scenario below).
- Availability checks: the "A" in confidentiality, integrity, and
  availability. Each Scenario Brief lists what the organization needs
  (authorized accounts, required links, and addresses). Breaking one fails
  an availability check, shows it in red and subtracts points until you
  undo the change.

2. THE ROUTINE (CHECKLIST)
--------------------------
[ ] 1. Pick the scenario pill (1 Recruit, 2 Operator, 3 Captain, 4 Two
       sites).
[ ] 2. Read the Activity panel top to bottom: the Scenario Brief
       (authorized administrators / users, required services, policy,
       warning and credentials) and the addressing table.
[ ] 3. Power on: click the device tab (it boots), answer no if a factory
       device offers the initial configuration dialog, press RETURN, and log
       in with the credentials from the Scenario Brief if the console asks.
[ ] 4. Investigation first: answer the Investigation questions in the
       Activity panel (two on Levels 1-3, four on Level 4; answers save as
       you type, checking is case-insensitive).
[ ] 5. Snapshot mentality: show running-config, show ip interface brief,
       show vlan brief, show interfaces trunk, show access-lists, and (on
       routers) show ip route on every device BEFORE changing anything.
       Compare accounts with the Scenario Brief.
[ ] 6. Fix by area: accounts and passwords; console and VTY lines; SSH
       (domain, RSA key, version 2); banner and services; VLANs and trunks;
       unused ports; port security / PortFast / BPDU guard / DHCP
       snooping; routing (static routes, OSPF); logging and NTP; ACLs.
       Watch the Progress Check after each change.
[ ] 7. Verify from the PCs: ipconfig, ping, tracert, ssh -l user address,
       telnet address (it should now be refused).
[ ] 8. Save on EVERY device: copy running-config startup-config (Enter at
       the filename prompt) or write. Test with reload if you dare.
[ ] 9. Finish / Debrief: read every miss, note the exact command, Reset
       lab and do it again faster.

3. SCENARIOS - SOLUTION WALKTHROUGH
-----------------------------------
Each check: title (points) [hardening area] / exact fix / why it matters.
Totals are 100 per scenario. Availability checks are listed last. Commands

3.1  Level 1 Recruit: Tutoring center
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Theme: Branch router hardening
  Grade: Sophomore. Learn it: Defense Ladder > Sophomore > Cisco: configure a
  switch and a router (https://freeapp4that.store/defense-ladder/#sophomore/s5).
Scenario Brief summary:
  You are the new network technician at the tutoring center, an after-school
  program with one branch router (R1) and a front-desk PC (PC1). The previous
  technician left R1 wide open: it still has its factory hostname, a plaintext
  enable password, an unused account, and Telnet access.
  Harden R1 so it meets the policy below. Work from R1's console tab and test
  from PC1. The R1 console starts password-free: press RETURN at the console to
  begin.
  Authorized administrators:
    - techlead (existing account, privilege 15) - keep it
    - netadmin (your account - create it with privilege 15 and a secret of 10+
      characters)
  Authorized users:
    - No other accounts are authorized. The "guest" account is not authorized.
  Required (availability checks protect these):
    - R1 GigabitEthernet0/0 (192.168.1.1) is the front-desk LAN and must stay up
      with its address.
    - SSH management from PC1 to R1 is required once you finish.
  Policy:
    - Privileged access uses an enable secret in place of a plaintext enable
      password.
    - Passwords and secrets are at least 10 characters.
    - The console and VTY lines require authentication; remote access is SSH
      only, with Telnet turned off.
    - A message-of-the-day banner warns unauthorized users and leaves out the
      word "welcome".
    - Every console and VTY line sets an exec-timeout shorter than the
      10-minute default on the line itself (for example, exec-timeout 5 0;
      0 0 turns the timeout off). Passwords are stored encrypted.
    - Unneeded services are off (HTTP server, DNS lookups). Unused interfaces
      are shut down.
    - Save the configuration when you are done.
  Warning: Keep every authorized account and keep GigabitEthernet0/0 online:
  removing either one fails an availability check.
  Credentials: R1 console: password-free for now (press RETURN). Enable
  password: letmein123 (replace it with an enable secret). PC1 is already
  addressed.
  Addressing (device | interface | address | mask | gateway):
    R1 | GigabitEthernet0/0 | 192.168.1.1 | 255.255.255.0 | -
    R1 | GigabitEthernet0/1 | unused | - | -
    PC1 | FastEthernet0 | 192.168.1.10 | 255.255.255.0 | 192.168.1.1
  Task list (shown in the Activity panel at this level):
    1. Set the hostname to R1.
    2. Configure an enable secret (10+ characters) and remove the plaintext
       enable password.
    3. Delete the unauthorized guest account; create netadmin with privilege 15
       and a secret.
    4. Protect the console with a password and login; set exec-timeout 5 0 on
       console and VTY.
    5. Make the VTY lines use login local and transport input ssh.
    6. Set a domain name, generate a 2048-bit RSA key, and force SSH version 2.
    7. Add a MOTD banner (without "welcome"), enable service
       password-encryption, require passwords of 10+ characters, and limit login
       attempts.
    8. Turn off the HTTP server and DNS lookups; shut down the unused interface
       GigabitEthernet0/1.
    9. Answer both investigation questions, then save with copy running-config
       startup-config.

Investigation answers:
  Q1: The VTY lines on R1 still carry a plaintext line password. What is it?
      (Hint: show running-config)
      ANSWER: cisco
  Q2: What is the file name of the IOS image R1 booted from? (Hint: show
      version)
      ANSWER: c1900-universalk9-mz.SPA.151-4.M4.bin
      also accepted: flash0:c1900-universalk9-mz.SPA.151-4.M4.bin,
        flash:c1900-universalk9-mz.SPA.151-4.M4.bin

Checks (22, 100 points):
   1. Hostname set to R1 (4 pts) [Secure configuration]
        R1(config)# hostname R1
        why: A named device is identifiable in logs and prompts; "Router" means
        nobody set it up.
   2. Enable secret configured (6 pts) [Account management]
        R1(config)# enable secret Str0ng-Enable-2026!
        why: The enable secret is hashed in the config; it guards privileged
        mode.
   3. Plaintext enable password removed (5 pts) [Account management]
        R1(config)# no enable password
        why: enable password is stored readably (or with weak type 7); the
        secret replaces it.
   4. Unauthorized account "guest" removed (6 pts) [Account management]
        R1(config)# no username guest
        why: Every unauthorized account is a way in; the scenario brief lists
        who is allowed.
   5. Administrator "netadmin" created with privilege 15 and a secret (6 pts)
      [Account management]
        R1(config)# username netadmin privilege 15 secret N3tadmin-2026!
        why: login local and SSH both need a local account; privilege 15 lands
        you in enable mode.
   6. Console line protected with a password and login (6 pts) [Access control]
        R1(config)# line console 0
        R1(config-line)# password C0nsole-Pass!
        R1(config-line)# login
        why: Without it anyone with a console cable owns the device.
   7. VTY lines use local user authentication (login local) (6 pts) [Access
      control]
        R1(config)# line vty 0 4
        R1(config-line)# login local
        why: SSH needs usernames; a shared line password cannot be audited or
        revoked per person.
   8. VTY lines accept SSH only (Telnet disabled) (6 pts) [Access control]
        R1(config-line)# transport input ssh
        why: Telnet sends passwords in clear text on the wire.
   9. Domain name configured (3 pts) [Access control]
        R1(config)# ip domain-name tutoring.lan
        why: The RSA key is named hostname.domain; IOS refuses to generate one
        without a domain.
  10. RSA key pair generated (2048 bits) (6 pts) [Access control]
        R1(config)# crypto key generate rsa general-keys modulus 2048
        why: Keys shorter than 2048 bits are considered weak; the key is what
        enables the SSH server.
  11. SSH version 2 enforced (5 pts) [Access control]
        R1(config)# ip ssh version 2
        why: SSHv1 has known weaknesses; v2 only is the standard.
  12. MOTD banner warns unauthorized users (and leaves out "welcome") (4 pts)
      [Secure configuration]
        R1(config)# banner motd #Authorized access only. Activity is monitored.#
        why: States that access is restricted and monitored. Cisco advises
        banners that reveal nothing about the device or owner; "welcome" reads
        as an invitation, and legal wording is a question for counsel.
  13. Service password-encryption enabled (4 pts) [Account management]
        R1(config)# service password-encryption
        why: Turns plaintext line and user passwords into type 7, which stops
        shoulder-surfing but is reversible obfuscation, not real encryption:
        secrets still need enable secret / username secret.
  14. Exec timeout shorter than 10 minutes on console and VTY (5 pts) [Access
      control]
        R1(config-line)# exec-timeout 5 0
        why: An idle, logged-in session left open is a free privileged shell.
        IOS already times out after 10 minutes by default, and show
        running-config leaves that default out; a shorter value, such as
        exec-timeout 5 0, shows in the configuration, where a reviewer can see
        it.
  15. Minimum password length set to 10 or more (3 pts) [Account management]
        R1(config)# security passwords min-length 10
        why: IOS then rejects new passwords and secrets shorter than that; set
        it before you set the passwords.
  16. Login attempts limited (login block-for) (4 pts) [Access control]
        R1(config)# login block-for 120 attempts 3 within 60
        why: Slows password guessing against the VTY lines.
  17. HTTP server disabled (3 pts) [Secure configuration]
        R1(config)# no ip http server
        why: An unneeded management interface is attack surface.
  18. DNS lookups disabled (no ip domain-lookup) (3 pts) [Secure configuration]
        R1(config)# no ip domain-lookup
        why: Stops typos from becoming long DNS "Translating..." hangs on the
        console.
  19. Unused interface GigabitEthernet0/1 shut down (3 pts) [Secure
      configuration]
        R1(config)# interface GigabitEthernet0/1
        R1(config-if)# shutdown
        why: Nobody can plug into a port that is administratively down.
  20. Configuration saved to startup-config (4 pts) [Secure configuration]
        R1# copy running-config startup-config
        why: Unsaved work vanishes on reload - this check reads the saved
        startup-config, just as a reload would.
  21. Investigation 1 answered (4 pts) [Investigation]
        Answer: cisco
        why: Reading the config before changing it is the first step of every
        assessment.
  22. Investigation 2 answered (4 pts) [Investigation]
        Answer: c1900-universalk9-mz.SPA.151-4.M4.bin
        why: show version tells you the software (and known bugs) you are
        defending.

Availability checks (pass while the required items keep working):
  - Fails if: Authorized administrator "techlead" removed (-8 pts)
        why: The scenario brief lists techlead as an authorized administrator;
        deleting a colleague's account locks them out of a device the center
        depends on.
  - Fails if: PC1 can no longer reach its gateway 192.168.1.1 (-10 pts)
        why: GigabitEthernet0/0 is a required service; shutting it or changing
        its address breaks the front desk.

3.2  Level 2 Operator: Branch library
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Theme: Access switch: VLANs, port security, and SSH
  Grade: Junior. Learn it: Defense Ladder > Junior > Cisco: VLANs, routing,
  and ACLs (https://freeapp4that.store/defense-ladder/#junior/j4); and, for port
  security, Defense Ladder > Sophomore > Cisco: configure a switch and a
  router (https://freeapp4that.store/defense-ladder/#sophomore/s5).
Scenario Brief summary:
  You are the network technician for the branch library. The branch has one
  access switch (S1) with two staff PCs and an uplink to the district router R1.
  District IT owns R1 and has already configured it as a router-on-a-stick: VLAN
  10 (STAFF, gateway 192.168.10.1) and VLAN 99 (MGMT, gateway 192.168.99.1, the
  native VLAN on the trunk).
  S1 was set up by a volunteer years ago: everything sits in VLAN 1, the switch
  is managed over Telnet with the password "cisco", and the uplink runs as an
  access port. Bring S1 up to policy. R1 is view-only for you: leave it exactly
  as it is.
  Authorized administrators:
    - libadmin (district account, privilege 15) - keep it
    - netadmin (your account - create it with privilege 15 and a secret of 10+
      characters)
  Authorized users:
    - No other accounts are authorized. "tempadmin" was never approved.
  Required (availability checks protect these):
    - PC1 and PC2 must keep connectivity to each other; after the migration both
      belong to VLAN 10 (STAFF).
    - The uplink GigabitEthernet0/1 to R1 is required. R1 is district-managed
      and stays as it is.
    - S1 must be manageable over SSH on VLAN 99 (192.168.99.2) from a staff PC.
  Policy:
    - User traffic uses VLANs above 1; management uses VLAN 99 (192.168.99.2/24,
      default gateway 192.168.99.1).
    - The uplink is an 802.1Q trunk with native VLAN 99, allowed VLANs 10 and
      99, and DTP negotiation turned off.
    - Unused ports are shut down and parked in VLAN 999 (PARKING).
    - PC-facing ports run port security (max 1-2 sticky addresses, violation
      shutdown or restrict), PortFast, and BPDU guard. PortFast belongs on edge
      ports only, so the uplink trunk stays free of it.
    - Enable secret only; passwords 10+ characters; a console password other
      than "cisco"; SSH only, with Telnet turned off; a banner without
      "welcome"; an exec-timeout shorter than the 10-minute default on every
      console and VTY line, set on the line itself (for example, exec-timeout
      5 0; 0 0 turns the timeout off); passwords encrypted; HTTP server and
      DNS lookups off.
    - Design note: this older branch layout uses VLAN 99 as both the native VLAN
      and the management VLAN. Level 4 shows the cleaner design: the native VLAN
      (99) carries no hosts, and management moves to a separate VLAN (Teachers,
      VLAN 20).
    - Save the configuration when you are done.
  Warning: Removing libadmin, breaking PC1-PC2 connectivity, or modifying R1
  fails an availability check.
  Credentials: S1 console password: cisco. S1 enable password: library (replace
  it). R1: no credentials are provided (user EXEC only).
  Addressing (device | interface | address | mask | gateway):
    R1 | Gi0/0.10 (VLAN 10) | 192.168.10.1 | 255.255.255.0 | -
    R1 | Gi0/0.99 (VLAN 99, native) | 192.168.99.1 | 255.255.255.0 | -
    S1 | Vlan99 (management) | 192.168.99.2 | 255.255.255.0 | 192.168.99.1
    PC1 | Fa0/1 (VLAN 10) | 192.168.10.11 | 255.255.255.0 | 192.168.10.1
    PC2 | Fa0/2 (VLAN 10) | 192.168.10.12 | 255.255.255.0 | 192.168.10.1

Investigation answers:
  Q1: What is the MAC address of PC2? (Hint: ipconfig /all on PC2, or show mac
      address-table on S1)
      ANSWER: 0001.B7D9.E350
  Q2: An unauthorized local account exists on S1. What is its username?
      ANSWER: tempadmin

Checks (27, 100 points):
   1. Hostname set to S1 (3 pts) [Secure configuration]
        S1(config)# hostname S1
        why: Logs, CDP, and prompts all show the name.
   2. Enable secret configured (4 pts) [Account management]
        S1(config)# enable secret L1brary-En@ble!
        why: Hashed, unlike the enable password.
   3. Plaintext enable password removed (4 pts) [Account management]
        S1(config)# no enable password
        why: "library" is readable in the config and easy to guess.
   4. Unauthorized account "tempadmin" removed (5 pts) [Account management]
        S1(config)# no username tempadmin
        why: A forgotten privilege-15 account is a permanent back door.
   5. Administrator "netadmin" created with privilege 15 and a secret (5 pts)
      [Account management]
        S1(config)# username netadmin privilege 15 secret N3tadmin-2026!
        why: Needed for login local and SSH.
   6. Console password changed from the default "cisco" (3 pts) [Access control]
        S1(config)# line console 0
        S1(config-line)# password C0nsole-Pass!
        S1(config-line)# login
        why: "cisco" is the first guess anyone makes.
   7. VTY lines use local user authentication (login local) (4 pts) [Access
      control]
        S1(config)# line vty 0 15
        S1(config-line)# login local
        why: Per-user accounts instead of one shared password.
   8. VTY lines accept SSH only (Telnet disabled) (5 pts) [Access control]
        S1(config-line)# transport input ssh
        why: Telnet exposes every keystroke, including passwords.
   9. Domain name set and 2048-bit RSA key generated (4 pts) [Access control]
        S1(config)# ip domain-name library.lan
        S1(config)# crypto key generate rsa general-keys modulus 2048
        why: No key, no SSH server.
  10. SSH version 2 enforced (3 pts) [Access control]
        S1(config)# ip ssh version 2
        why: Disables the weaker protocol version.
  11. MOTD banner warns unauthorized users (3 pts) [Secure configuration]
        S1(config)# banner motd #Authorized library staff only. Activity is
            monitored.#
        why: Legal notice shown before login.
  12. Service password-encryption enabled (3 pts) [Account management]
        S1(config)# service password-encryption
        why: Obscures line passwords in show running-config.
  13. Exec timeout shorter than 10 minutes on console and VTY (3 pts) [Access
      control]
        S1(config-line)# exec-timeout 5 0
        why: Closes abandoned sessions.
  14. HTTP server disabled (3 pts) [Secure configuration]
        S1(config)# no ip http server
        why: Removes the web management interface.
  15. DNS lookups disabled (2 pts) [Secure configuration]
        S1(config)# no ip domain-lookup
        why: Prevents typo lookups from hanging the console.
  16. VLAN 10 "STAFF" created and both PC ports are access ports in it (4 pts)
      [Secure configuration]
        S1(config)# vlan 10
        S1(config-vlan)# name STAFF
        S1(config)# interface range fa0/1 - 2
        S1(config-if-range)# switchport mode access
        S1(config-if-range)# switchport access vlan 10
        why: User traffic leaves the default VLAN; access mode stops DTP games
        on user ports.
  17. Management moved to VLAN 99 (Vlan99 192.168.99.2 up, Vlan1 shut down) (5
      pts) [Secure configuration]
        S1(config)# vlan 99
        S1(config-vlan)# name MGMT
        S1(config)# interface vlan 99
        S1(config-if)# ip address 192.168.99.2 255.255.255.0
        S1(config-if)# no shutdown
        S1(config)# interface vlan 1
        S1(config-if)# no ip address
        S1(config-if)# shutdown
        why: Management on VLAN 1 is reachable from every unconfigured port.
        (Larger networks also keep management off the native VLAN; this branch
        layout keeps 99 for both, and Level 4 separates them.)
  18. Default gateway corrected to 192.168.99.1 (3 pts) [Secure configuration]
        S1(config)# ip default-gateway 192.168.99.1
        why: The switch replies to off-subnet managers through its gateway on
        the MGMT VLAN.
  19. Uplink Gi0/1 is a trunk: native VLAN 99, allowed 10,99, nonegotiate (5
      pts) [Secure configuration]

        in the allowed list, because a trunk drops traffic, spanning tree
        included, for any VLAN missing from that list (show interfaces trunk
        then lists 99 among the allowed and forwarding VLANs).
   5. SwB unused ports (Fa0/3-24, Gi0/2) parked in VLAN 999 and shut down (4
      pts) [Secure configuration]
        SwB(config)# interface range fa0/3 - 24 , gi0/2
        SwB(config-if-range)# switchport mode access
        SwB(config-if-range)# switchport access vlan 999
        SwB(config-if-range)# shutdown
        why: A shut port stays closed, and if someone enables it by mistake it
        lands in a dead-end VLAN that is separate from the native VLAN.
   6. SwB management: Vlan20 10.2.20.2 up, gateway 10.2.20.1, Vlan1 shut down (4
      pts) [Secure configuration]
        SwB(config)# interface vlan 20
        SwB(config-if)# ip address 10.2.20.2 255.255.255.0
        SwB(config-if)# no shutdown
        SwB(config-if)# exit
        SwB(config)# ip default-gateway 10.2.20.1
        SwB(config)# interface vlan 1
        SwB(config-if)# shutdown
        why: The SVI comes up once VLAN 20 exists and has an up port. The
        default gateway lets the switch answer managers at the other site.
   7. SwB SSH: hostname SwB, domain, 2048-bit key, version 2, netadmin, SSH-only
      VTY 0-15 (5 pts) [Access control]
        Switch(config)# hostname SwB
        SwB(config)# ip domain-name school.lan
        SwB(config)# crypto key generate rsa general-keys modulus 2048
        SwB(config)# ip ssh version 2
        SwB(config)# username netadmin privilege 15 secret Adm1n-B1
        SwB(config)# line vty 0 15
        SwB(config-line)# login local
        SwB(config-line)# transport input ssh
        why: SSH encrypts the session, and login local ties every login to a
        named account.
   8. SwB VTY ACL 20: Teachers at both sites only (access-class 20 in on vty 0
      15) (3 pts) [Access control]
        SwB(config)# access-list 20 permit 10.1.20.0 0.0.0.255
        SwB(config)# access-list 20 permit 10.2.20.0 0.0.0.255
        SwB(config)# line vty 0 15
        SwB(config-line)# access-class 20 in
        why: Only Teachers see a login prompt: SSH from a Students PC gets "%
        Connection refused by remote host" instead.
   9. RtrB G0/0 up with subinterfaces .10, .20, and .30 (dot1Q plus gateway
      addresses) (7 pts) [Secure configuration]
        RtrB(config)# interface g0/0
        RtrB(config-if)# no shutdown
        RtrB(config-if)# interface g0/0.10
        RtrB(config-subif)# encapsulation dot1Q 10
        RtrB(config-subif)# ip address 10.2.10.1 255.255.255.0
        (repeat for .20 with 10.2.20.1 and .30 with 10.2.30.1)
        why: Router-on-a-stick: one physical link carries every VLAN, and each
        subinterface is the gateway for one of them. The tag comes first; IOS
        refuses an address on a LAN subinterface without one.
  10. RtrB G0/0.99: encapsulation dot1Q 99 native, without an IP address (4 pts)
      [Secure configuration]
        RtrB(config)# interface g0/0.99
        RtrB(config-subif)# encapsulation dot1Q 99 native
        why: Both ends of the trunk agree that untagged frames belong to VLAN
        99, which ends the CDP native VLAN mismatch messages on SwB. The native
        VLAN carries no hosts, so it needs no address.
  11. RtrB G0/2 10.0.0.2/30 and G0/1 198.51.100.2/30 up (4 pts) [Secure
      configuration]
        RtrB(config)# interface g0/2
        RtrB(config-if)# ip address 10.0.0.2 255.255.255.252
        RtrB(config-if)# no shutdown
        RtrB(config-if)# interface g0/1
        RtrB(config-if)# ip address 198.51.100.2 255.255.255.252
        RtrB(config-if)# no shutdown
        why: A /30 holds exactly two hosts, one per end of a point-to-point
        link. Router ports start shut down on a fresh ISR.
  12. RtrB static host route: ip route 8.8.8.8 255.255.255.255 198.51.100.1 (5
      pts) [Secure configuration]
        RtrB(config)# ip route 8.8.8.8 255.255.255.255 198.51.100.1
        why: The /32 mask matches the resolver alone, so only that destination
        uses this uplink path. The route installs while 198.51.100.1 sits on an
        up, connected subnet.
  13. RtrB OSPF neighbour FULL with RtrA (5 pts) [Troubleshooting]
        RtrB(config)# router ospf 1
        RtrB(config-router)# router-id 2.2.2.2
        RtrB(config-router)# network 10.0.0.0 0.0.0.3 area 0
        RtrB(config-router)# network 10.2.0.0 0.0.255.255 area 0
        why: Neighbours form when both ends enable OSPF on the shared subnet in
        the same area. Each router then learns the other site's VLANs as O
        routes, so OSPF replaces hand-typed inter-site static routes.
  14. RtrB redistributes its static route: redistribute static subnets (4 pts)
      [Secure configuration]
        RtrB(config)# router ospf 1
        RtrB(config-router)# redistribute static subnets
        why: Without subnets, classic IOS 15 redistributes classful networks
        only and drops the /32. With it, RtrB floods a type-5 LSA for 8.8.8.8
        (show ip ospf database on RtrA); RtrA installs it as O E2 8.8.8.8
        [110/20] only when its own static route leaves the table.
  15. RtrB SSH: hostname RtrB, domain, 2048-bit key, version 2, netadmin,
      SSH-only on every VTY line (3 pts) [Access control]
        Router(config)# hostname RtrB
        RtrB(config)# ip domain-name school.lan
        RtrB(config)# crypto key generate rsa general-keys modulus 2048
        RtrB(config)# ip ssh version 2
        RtrB(config)# username netadmin privilege 15 secret Adm1n-B2
        RtrB(config)# line vty 0 15
        RtrB(config-line)# login local
        RtrB(config-line)# transport input ssh
        why: show running-config lists every VTY range the router has: line vty
        0 4, plus line vty 5 15 once line vty 0 15 creates those lines. One
        range left open to Telnet leaves the whole router open, so every range
        counts.
  16. RtrB VTY ACL 20: Teachers at both sites only, on every VTY line (4 pts)
      [Access control]
        RtrB(config)# access-list 20 permit 10.1.20.0 0.0.0.255
        RtrB(config)# access-list 20 permit 10.2.20.0 0.0.0.255
        RtrB(config)# line vty 0 15
        RtrB(config-line)# access-class 20 in
        why: access-class filters who may open a session to the router itself,
        whatever address they aim at. The implicit deny at the end refuses
        everyone else.
  17. Enable secret on SwB and RtrB (in place of an enable password) (3 pts)
      [Account management]
        SwB(config)# enable secret En@ble-B1
        RtrB(config)# enable secret En@ble-B2
        why: The secret is stored hashed and guards privileged mode.
  18. Console password with login on SwB and RtrB (2 pts) [Access control]
        SwB(config)# line console 0
        SwB(config-line)# password C0nsole-B1
        SwB(config-line)# login
        RtrB(config)# line console 0
        RtrB(config-line)# password C0nsole-B2
        RtrB(config-line)# login
        why: Without it, anyone with a console cable reaches the command line
        password-free.
  19. MOTD and login banners on SwB and RtrB (3 pts) [Secure configuration]
        (config)# banner motd #Authorized school staff only. Activity is
            monitored.#
        (config)# banner login #Site B network equipment. Sign in with your own
            account.#
        why: The console shows the MOTD and then the login banner before the
        password prompt; SSH shows the login banner before authentication.
  20. Configurations saved on SwB and RtrB (2 pts) [Secure configuration]
        # copy running-config startup-config
        why: A reload otherwise boots both devices back to factory defaults (the
        VLANs alone survive, in vlan.dat).
  21. Student-B reaches Teacher-B (inter-VLAN routing) (3 pts) [Troubleshooting]
        Student-B> ping 10.2.20.10
        why: Proves the access ports, the trunk, and the router-on-a-stick
        subinterfaces work together.
  22. Teacher-B reaches Teacher-A across the inter-site link (4 pts)
      [Troubleshooting]
        Teacher-B> ping 10.1.20.10
        why: Each router reaches the other site only through the O routes OSPF
        installs.
  23. Student-B reaches the resolver at 8.8.8.8 (3 pts) [Troubleshooting]
        Student-B> ping 8.8.8.8
        why: Proves the host route and the ISP path. To see the backup path,
        shut RtrB G0/1: the ping still works over Site A through the O E2 route.
        Then run no shutdown to bring the uplink back.
  24. Investigation 1 answered (2 pts) [Investigation]
        Answer: S
        why: S marks a static route; the local static wins over OSPF because its
        administrative distance is lower.
  25. Investigation 2 answered (2 pts) [Investigation]
        Answer: O
        why: O marks an intra-area OSPF route: RtrA learned Site B's VLANs from
        RtrB.
  26. Investigation 3 answered (2 pts) [Investigation]
        Answer: 1
        why: Static routes default to distance 1 and OSPF uses 110, so the
        router prefers the static route while it is installed.
  27. Investigation 4 answered (2 pts) [Investigation]
        Answer: subnets
        why: Classic IOS 15 redistributes only classful networks into OSPF
        unless you add subnets. IOS XE adds subnets for you and shows it in the

Availability checks (pass while the required items keep working):
  - Fails if: Site A device (SwA or RtrA) or the ISP router changed (-10 pts)
        why: Site A belongs to the Site A team and the ISP router to the
        provider. Read their configurations freely and leave them exactly as

  - Fails if: Site A Teachers locked out of SSH to SwB or RtrB (-8 pts)

5. THE REAL DEVICE DIFFERS HERE
-------------------------------
- Real IOS pauses long output with --More-- (Space continues, q quits) unless
  you set terminal length 0. The lab never pauses.
- Generating a 2048-bit key takes several seconds on real hardware; reload
  takes minutes, not two seconds.
- Real routers answer an unknown first word in EXEC mode with Translating
  "word"...domain server (255.255.255.255) and hang for a while unless you
  configured no ip domain-lookup. The lab shows the ^ marker instead.
- Packet Tracer and real switches learn sticky MAC addresses only when the
  PC actually sends traffic; the lab learns them as soon as sticky is
  enabled on a port whose PC is connected (and on any ping through it).
- Real syslog and NTP servers answer; here 192.168.99.50 is only a name in
  the Scenario Brief. show ntp status will always say unsynchronized.
- On a real device Telnet/SSH from a PC needs the PC to resolve ARP and the
  first ping often loses one packet (the lab mimics that first loss).
- Real IOS versions differ in wording (ip domain name vs ip domain-name,
  secret 5 vs secret 9). The lab follows Packet Tracer / IOS 15.1.
- login block-for quiet mode, ACL access-class and port security are real
  here, but a mis-typed ACL on a real device can lock you out of your own
  SSH session; always keep a console connection open while testing.
- The lab resets a device's log and clock on reload like a router with
  no battery-backed clock (Mar 1 1993); real switches keep their log in
  RAM only as well, so save and export logs before a reload in real life.
- Browser notes: Ctrl+W/Ctrl+T belong to the browser; use Ctrl+U to clear a
  line. On phones, type ? at the end of the line to get help.
- OSPF: neighbours reach FULL at once here; a real router takes a few
  seconds (hello 10 s, dead 40 s) and passes through INIT, 2WAY, EXSTART,
  EXCHANGE, and LOADING first. Ethernet links elect a DR and a BDR, so
  show ip ospf neighbor reads FULL/DR or FULL/BDR; point-to-point links
  read FULL/ -. DR election is non-preemptive: the first router up on the
  segment stays DR; the higher router ID wins only when both start
  together (a real router waits 40 seconds before it elects; the lab
  elects at once). A reload drops the router's links, so the BDR takes over
  as DR and keeps the role when the router returns; the lab logs the
  neighbours' link and ADJCHG messages at the moment of the reload, while a
  real network spreads them over the boot. The lab recalculates the router
  ID from the configuration, while a real router keeps the ID it chose at
  start-up until a reload or clear ip ospf process.
- OSPF redistribution: classic IOS 15 (this lab and Packet Tracer) needs
  redistribute static subnets to carry a /32; without subnets it warns
  "% Only classful networks will be redistributed". IOS XE redistributes
  subnets by default and shows the subnets keyword for you.
- Static routes: the lab installs a static route while its next hop sits on
  an up, connected subnet. Real IOS also resolves a next hop recursively
  through other routes.
- Router models: the Level 4 routers are 2911s with ports g0/0-g0/2. A
  factory ISR G2 has VTY lines 0-4 only; line vty 0 15 creates lines 5-15,
  and show running-config then lists line vty 0 4 and line vty 5 15 (the
  lab's 2911 does the same, and a 2960 lists its 16 lines the same way).
  ISR 4000 routers running IOS XE name their ports g0/0/0 instead.
- Trunks: the 2960 trunks with 802.1Q only, so it rejects switchport trunk
  encapsulation dot1q; a multilayer switch such as the 3560 needs that
  command before switchport mode trunk.
- CDP repeats a native VLAN mismatch message every minute on a real switch;
  the lab prints it when the mismatch appears.
- VLANs: in VTP server mode (the default) VLANs live in vlan.dat only; in
  VTP transparent mode IOS also writes them into the running
  configuration.
- The Level 4 ISP router routes the school's private 10.x ranges back to
  each site. A real provider does that only after NAT on the school's
  routers, which sits outside this lab.
- Numbered ACLs: on a real device "no access-list 10 permit host X"
  deletes all of access list 10, and a VTY access-class that points at a
  missing list no longer filters anything. Edit single entries through
  "ip access-list standard 10" and sequence numbers instead (the lab
  behaves the same way).
